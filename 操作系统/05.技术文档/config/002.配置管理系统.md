# 配置管理系统

## 1. 概述

配置管理系统（Config Management System）是一多 OS 的「意志层」。它遵循自举编程原则——系统读取自身的 YAML 配置文件来决定行为，所有构建参数和运行时行为从配置中递归派生，实现零硬编码。

### 核心设计原则

| 原则 | 说明 |
|------|------|
| **配置即代码** | YAML 配置文件是组件 DNA 的唯一真实来源，所有构建参数从配置派生 |
| **递归解析** | `YamlNode` 递归解析器替代正则平扫，支持任意深度的嵌套结构 |
| **自举入口** | `bootstrap.yaml` 是固定入口文件，通过遍历和递归选择组件实现 |
| **零硬编码** | 库路径、系统库、编译选项全部从组件 YAML 读取 |
| **热更新可溯** | 每次配置变更记录版本号，变化可追溯 |

## 3. 固定入口与自举遍历

### 3.1 入口文件：`configs/bootstrap.yaml`

每个模块的根目录下有一个 `bootstrap.yaml` 作为固定入口。系统启动时首先读取该文件，确定运行时实现（如 WAMR 用 real 还是 stub）。

**bootstrap.yaml 格式：**

```yaml
runtime:
  implementation: wamr-real
  auto-detect: true
  fallback: wamr-stub
```

### 3.2 自举遍历流程

```
bootstrap.yaml ──→ 确定实现名称（如 wamr-real）
      │
      ▼
configs/components/wamr-runtime.yaml
      │
      ├── implementations:
      │   ├── wamr-real  → 真实 WAMR 构建参数
      │   └── wamr-stub  → 零依赖回退参数
      │
      ▼ (递归匹配)
matching implementation's build 节点
      │
      ├── include-paths:  [...]
      ├── native-library: "third_party/.../liblibiwasm.a"
      ├── system-libs:    {windows: [ws2_32, ntdll], ...}
      └── linker-opts:    "-Wl,--whole-archive ..."
```

### 3.3 递归 YAML 解析

`runtime/config/config_loader.mbt` 实现了纯 MoonBit 的递归 YAML 解析器：

```moonbit
pub enum YamlNode {
  YamlScalar(String)
  YamlMapping(Array[(String, YamlNode)])  // 递归
  YamlSeq(Array[YamlNode])                // 递归
}

pub fn parse_yaml(content : String) -> Result[YamlNode, String]
```

辅助函数（通过递归遍历提取配置）：

```moonbit
pub fn get_scalar(node : YamlNode, key : String) -> String?
pub fn get_mapping(node : YamlNode, key : String) -> YamlNode?
pub fn get_seq(node : YamlNode, key : String) -> YamlNode?
```

## 4. 组件配置格式规范

### 4.1 标准格式

每个组件必须遵循以下格式（参考 `008.组件配置格式规范.md`）：

```yaml
# configs/components/<component-name>.yaml
component:
  id: <component-id>          # 唯一标识
  type: <component-type>      # 组件类型（native/wasm/composite）
  description: <description>  # 简要描述
  author: <author>            # 作者
  version: <version>          # 版本号

default-strategy:
  preferred: <impl-name>       # 首选实现
  fallbacks:                   # 回退列表
    - <impl-name>
  selection-rules:             # 选择规则
    - condition: <condition>
      implementation: <impl-name>

implementations:
  - name: <impl-name>          # 实现名称
    description: <desc>        # 实现描述
    compatibility: <0-100>     # 兼容性评分
    build:
      native-library: <path>   # 原生库路径
      include-paths:           # 编译包含路径
        - <path>
      system-libs:             # 系统库（按平台）
        windows: [<lib>, ...]
        linux: [<lib>, ...]
        macos: [<lib>, ...]
      linker-opts: <flags>     # 链接选项
      cflags: <flags>          # C 编译选项
```

### 4.2 完整示例：`wamr-runtime.yaml`

```yaml
component:
  id: wamr-runtime
  type: native
  description: WebAssembly Micro Runtime
  author: yiduo
  version: 1.0.0

default-strategy:
  preferred: wamr-real
  fallbacks:
    - wamr-stub
  selection-rules:
    - condition: os == windows && has_cmake
      implementation: wamr-real
    - condition: auto-detect == true && has_wamr_header
      implementation: wamr-real
    - condition: true
      implementation: wamr-stub

implementations:
  - name: wamr-real
    description: 真实 WAMR 运行时实现
    compatibility: 80
    build:
      native-library: "third_party/wasm-micro-runtime/build/liblibiwasm.a"
      include-paths:
        - "third_party/wasm-micro-runtime/core/iwasm/include"
      system-libs:
        windows: [ws2_32, ntdll]
        linux: [pthread, dl, m]
        macos: [pthread, dl, m]
      linker-opts: "-Wl,--whole-archive {native-library} -Wl,--no-whole-archive"
      cflags: "-DWAMR_DISABLE_HW_BOUND_CHECK=1"

  - name: wamr-stub
    description: 零依赖回退实现
    compatibility: 30
    build:
      native-library: ""
      include-paths: []
      system-libs:
        windows: []
        linux: []
        macos: []
      linker-opts: ""
      cflags: ""
```

## 5. CRUD 操作

### 5.1 FileSystem 接口扩展

在 `runtime/core/file_system.mbt` 中定义了完整的 CRUD 接口：

```moonbit
pub struct FileSystem {
  read_to_string : (String) -> Result[String, String]     // R
  list_dir : (String) -> Result[Array[String], String]    // 列表
  write_to_string : (String, String) -> Result[Unit, String] // C/U
  delete_file : (String) -> Result[Unit, String]          // D
  file_exists : (String) -> Bool                          // 存在检查
}
```

### 5.2 ConfigManager API

`runtime/config/config_manager.mbt` 提供了配置 CRUD：

| 操作 | 方法 | 说明 |
|------|------|------|
| **Create** | `create_config(fs, file_name, content)` | 创建新配置文件，文件已存在则返回错误 |
| **Read** | `read_config(fs, file_name)` | 读取 YAML 原始内容 |
| **Read** | `read_and_parse(fs, file_name)` | 读取并解析为 `ComponentDescriptor` |
| **Update** | `write_config(fs, file_name, content)` | 写入/覆写配置文件，返回 `ConfigChange` |
| **Delete** | `delete_config(fs, file_name)` | 删除配置文件，返回 `ConfigChange` |
| **List** | `list_configs(fs)` | 列出配置目录下所有 `.yaml`/`.yml` 文件 |

### 5.3 ConfigChange 追踪

每次写/删操作返回 `ConfigChange` 记录：

```moonbit
pub struct ConfigChange {
  file_path : String
  component_name : String
  change_type : ChangeType    // Created | Updated | Deleted
  previous_hash : Int         // 旧文件哈希（新建时为 0）
  new_hash : Int              // 新文件哈希（删除时为 0）
}
```

### 5.4 使用示例

```moonbit
/// 创建配置管理器
let fs = @fs.create_native_fs()
let mgr = @config.ConfigManager::create("configs/components")

/// 读取配置
let content = mgr.read_config(fs, "my-component.yaml")

/// 创建新配置
let change = mgr.create_config(fs, "new-component.yaml", yaml_content)

/// 更新配置
let change = mgr.write_config(fs, "existing.yaml", updated_yaml)

/// 删除配置
let change = mgr.delete_config(fs, "obsolete.yaml")

/// 列出所有配置
let files = mgr.list_configs(fs)
```

## 6. 热更新机制

### 6.1 架构

热更新机制在 `runtime/config/hot_update.mbt` 中实现：

```
配置变更（CRUD）
    │
    ▼
ConfigManager.notify_listeners(change)
    │
    ├──→ HotUpdateCoordinator.apply_hot_update()
    │        │
    │        ├── 验证配置合法性
    │        ├── 查找组件 ID
    │        ├── unregister_handler(旧ID)
    │        ├── mark_component_stopped(旧ID)
    │        └── register(新组件)
    │
    └──→ 返回 HotUpdateResult
         ├── Success(name)     → 更新成功
         ├── Skipped(reason)   → 跳过更新
         └── Failed(error)     → 更新失败
```

### 6.2 HotUpdateConfig

```moonbit
pub struct HotUpdateConfig {
  enabled : Bool                     // 是否启用热更新
  auto_register_on_create : Bool     // 配置创建时自动注册组件
  auto_unregister_on_delete : Bool   // 配置删除时自动停用组件
}
```

### 6.3 安全保证

| 场景 | 行为 |
|------|------|
| 配置更新但内容未变 | 跳过：`Skipped("内容无变化")` |
| 更新后配置解析失败 | 拒绝：`Failed("配置解析失败")`，旧组件继续运行 |
| 创建时自动注册已禁用 | 跳过：`Skipped("创建时自动注册已禁用")` |
| 组件未找到 | 以新组件 ID 注册 |
| 热更新全局禁用 | 跳过：`Skipped("热更新已禁用")` |

### 6.4 监听器模式

```moonbit
/// 注册变更监听器
let (mgr2, listener_id) = mgr.on_change(fn(change : ConfigChange) {
  println("配置变更: " + change.file_path)
})

/// 执行热更新
let (scheduler2, result) = @config.apply_hot_update(
  change, fs, scheduler, mgr2, @config.HotUpdateConfig::default(),
)

/// 移除监听器
let mgr3 = mgr2.remove_listener(listener_id)
```

## 7. 成熟方案参考

### 7.1 行业参考

| 方案 | 适用场景 | 借鉴要点 |
|------|---------|---------|
| **Kubernetes CRD + Controller** | 声明式配置 + 控制器模式 | ConfigMap 作为配置源，Controller 监听变化并 reconcile 状态 |
| **etcd + Watch** | 分布式配置中心 | Watch 机制实现配置变更的实时推送 |
| **Android ContentProvider** | 本地配置管理 | URI-based 配置访问，权限控制 |
| **Spring Cloud Config** | 微服务配置管理 | 配置中心化、版本管理、动态刷新 |
| **NixOS** | 声明式系统配置 | 单源真理，不可变配置，回滚机制 |

### 7.2 本系统借鉴的设计

| 借鉴来源 | 在系统中的体现 |
|---------|--------------|
| CRD 模式 | 组件 YAML 配置文件 → ComponentDescriptor |
| Controller 模式 | ConfigManager 监听变更 → HotUpdateCoordinator 执行 reconcile |
| ConfigMap 模式 | 配置与组件解耦，支持运行时替换 |
| 不可变配置（NixOS） | 每次写操作记录 hash 变更，ConfigChange 可追溯 |
| 自举原则 | 系统读取自身 YAML 配置决定行为（区别于外部配置中心） |

### 7.3 更好方案

相比外部配置中心（如 etcd + cloud native 配置服务），本系统采用**自举配置**方案的优势：

| 维度 | 外部配置中心 | 自举配置（本方案） |
|------|-------------|------------------|
| **依赖** | 需要 etcd/server | 零依赖，纯文件系统 |
| **启动安全** | 依赖网络和服务可用 | 本地文件保证启动 |
| **复杂度** | 高（分布式一致性） | 低（文件 + Hash 校验） |
| **自举性** | 配置中心本身需要配置 | 系统读取自身配置 |
| **适用场景** | 分布式微服务 | 嵌入式/OS 级组件配置 |
