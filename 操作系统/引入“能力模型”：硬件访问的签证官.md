### ️ 引入“能力模型”：硬件访问的签证官

Wasm 沙箱默认是“无权限”的。UniHAL 不应只是硬件的抽象，更应是硬件的**守门人**。我们需要在接口层引入**基于能力的访问控制**。

**设计思路：**
不要直接暴露 `open(device_id)`，而是要求调用者出示“凭证”。这个凭证由宿主（Host/OS）颁发。

**WIT 接口补充：**

```
// 定义一个不可伪造的“能力令牌”
resource io_capability {
    // 令牌内部包含权限元数据，对应用透明
    constructor(metadata: string);
}

interface serial {
    // 必须持有“能力令牌”才能打开设备
    // 这防止了恶意组件随意扫描或访问敏感硬件（如摄像头、串口）
    open(capability: io_capability, baud_rate: u32) -> result<stream, Error>;
}
```

**为什么这很完美？**

- **零信任架构**：默认拒绝所有硬件访问，除非显式授权。
- **细粒度权限**：你可以给一个组件“只读”摄像头的能力，或者“只能写入”日志串口（`/dev/ttyS0`）的能力，而无需给它 Root 权限。

### ️ 引入“零拷贝共享内存”：突破 Wasm 的性能墙

Wasm 的传统内存模型是线性的，外部无法直接访问。对于高频硬件（如网卡、摄像头、存算阵列），如果在 Host 和 Guest 之间来回拷贝数据，性能会崩塌。

**设计思路：**
UniHAL 必须支持**外部内存借用**。允许硬件驱动直接将 DMA 缓冲区的指针“映射”给 Wasm 组件，实现零拷贝。

**WIT 接口补充：**

```
// 定义一种特殊的“借用视图”
resource borrow_view {
    // 获取底层缓冲区的只读/读写视图
    // 这里返回的不是数据副本，而是直接操作 Host 内存的句柄
    get_buffer() -> buffer_handle;
}

interface dma_engine {
    // 申请一块可用于 DMA 传输的共享内存
    alloc_shared(size: u32) -> borrow_view;
    
    // 触发 DMA 传输，直接读写共享内存
    transfer(view: borrow_view, direction: Direction) -> result<(), Error>;
}
```

**为什么这很完美？**

- **性能质变**：处理 4K 视频流或 10Gbps 网络包时，CPU 占用率几乎为零。
- **统一抽象**：对开发者来说，`borrow_view` 看起来就像普通的内存，但底层其实是直接映射的硬件缓冲区。

### 引入“异步事件流”：告别轮询地狱

传统的 HAL 往往提供 `read()` 阻塞接口，或者让用户写回调函数。在跨语言环境中，回调函数极其容易出错（例如 Python 的 GIL 锁问题）。UniHAL 应该采用**基于流（Stream）的异步模型**。

**设计思路：**
将硬件事件（按键按下、网络包到达、传感器阈值触发）抽象为标准的 `stream<T>`。

**WIT 接口补充：**

```
interface input {
    // 定义一个按键事件
    record key_event {
        code: u32,
        pressed: bool,
        timestamp: u64,
    }

    // 返回一个“事件流”，组件可以用 async/await 优雅地消费它
    // 这比回调函数更符合现代 Rust/JS/Python 的编程范式
    subscribe_keys() -> stream<key_event>;
}
```

**为什么这很完美？**

- **现代化编程**：开发者可以用 `for await (event in keyboard.subscribe_keys())` 这样的语法，代码极其清晰。
- **背压支持**：Wasm 的 Stream 原生支持背压。如果应用处理不过来（比如 AI 推理太慢），硬件驱动会自动暂停产生事件，防止内存溢出。

### 引入“遥测元数据”：自带说明书的硬件

在传统的 Linux 开发中，你经常不知道某个 GPIO 到底是控制 LED 的还是控制复位脚的，只能去翻几百页的数据手册。

**设计思路：**
UniHAL 的每个资源对象都应该携带**自描述的元数据**。这不仅是调试工具，更是**AI 辅助编程**的基础。

**WIT 接口补充：**

```
interface hardware_info {
    // 获取资源的详细描述
    get_metadata() -> Metadata;
}

record Metadata {
    // 厂商信息
    vendor: string,
    // 物理位置描述（例如："Board: RaspberryPi, Pin: GPIO_17"）
    physical_location: string,
    // 支持的协议版本
    protocol_version: string,
}
```

**为什么这很完美？**

- **可观测性**：系统可以自动生成硬件拓扑图。
- **AI 友好**：当 AI 助手（Copilot）看到代码中引用了一个 `sensor` 对象时，它可以读取 `get_metadata()`，然后告诉开发者：“注意，这个传感器是 I2C 地址 0x48，最大采样率 100Hz”，从而自动生成正确的初始化代码。
