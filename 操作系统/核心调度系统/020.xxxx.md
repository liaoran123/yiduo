---

### 阶段 1：加载基础组件（依然裸机）

一多 OS 已经在裸机上运行了，现在通过配置加载更多组件：

```yaml
# bootstrap_phase1.yaml (存储在 Flash 中)
apiVersion: yiduo.dev/v1alpha1
kind: System
spec:
  components:
    # Flash 驱动组件（替换简单的存储访问）
    - name: flash_storage
      type: native
      path: /flash/components/storage.wasm
    
    # 文件系统组件（构建在 Flash 之上）
    - name: littlefs
      type: wasm
      path: /flash/components/fs.wasm
      requires: flash_storage
```

**一多 OS 做的事情（在裸机上）**：
1. 从 Flash 读取配置
2. 加载这些组件
3. 系统功能增强了！

---

### 阶段 2：加载更多组件（依然裸机）

继续用配置文件加载更多功能：

```yaml
# bootstrap_phase2.yaml
spec:
  inherit:
    - scheduler_core
    - flash_storage
    - littlefs
  
  components:
    # 网络组件
    - name: wifi_driver
      type: native
    
    # TCP/IP 协议栈
    - name: tcpip_stack
      type: wasm
      requires: wifi_driver
    
    # 完整配置解析器
    - name: config_parser_full
      type: wasm
```

---

### 阶段 3：自举完成（还是裸机！）

最终，一多 OS 可以在裸机上"自己编译自己"（或者说重新打包自己）：

```yaml
# bootstrap_final.yaml
spec:
  # 目标：更新一多 OS 自己
  target: yiduo_os_self_update
  
  components:
    # 打包工具组件
    - name: flash_packer
      type: wasm
    
    # 编译器组件（可选）
    - name: moonbit_compiler
      type: native
      requires: flash_storage
  
  # 操作
  action:
    - update_bootloader
    - update_kernel
    - update_components
```

## 💻 启动流程（真正的裸机）

```
1. CPU 上电复位
   ↓
2. 执行启动引导代码（汇编）
   - 初始化堆栈
   - 配置时钟
   - 初始化 RAM
   ↓
3. 跳转到 C 入口点
   - 初始化硬件
   - 初始化 MoonBit 运行时
   ↓
4. 调用 MoonBit 的 main()
   - 这是一多 OS 的入口！
   ↓
5. 从 Flash 读取 bootstrap.yaml
   ↓
6. 加载配置中的组件
   ↓
7. 启动调度循环
   ↓
8. 一多 OS 运行中！
```

## 🚀 为什么这是革命性的？

### 传统操作系统开发
```
写引导代码 → 写内核 → 写驱动 → 写文件系统 → 写应用 → 编译 → 烧录 → 测试
                                 (每次修改都要重新编译整个系统)
```

### 一多 OS 方式
```
写最小内核 → 烧录 → 启动 → 写配置 → 加载组件 → 测试 → 改配置 → 重新加载
              (从这里开始，不用重新编译内核！只改配置！)
```
