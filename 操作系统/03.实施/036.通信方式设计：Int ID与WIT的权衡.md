# 通信方式设计：Int ID 与 WIT 的完美配合

> **重要设计决策记录**：WIT（编译期）和 Int ID（运行期）如何完美配合

---

## 🎯 核心结论

> **WIT和Int ID不是互斥的——它们是编译期和运行期的完美配合！**

| 阶段 | 技术 | 价值 |
|------|------|------|
| **开发/编译期** | WIT | 类型安全、接口契约、跨语言、生态兼容 |
| **运行期** | Int ID | 极致性能、O(1)查找、确定性行为 |

**两者关系**：WIT →（编译时转换）→ Int ID →（运行）→ 极致性能

---

## 💡 核心洞察：不是二选一，是前道和后道

```
开发时（编译期）                    运行时
─────────────                    ─────────
WIT接口定义  ──代码生成器──→  Int ID映射表  ──→  高性能整数调用
    │                              │
    │                              │
  类型安全                      性能最优
  (给人看)                      (给机器跑)
```

**WIT的价值在编译期**：类型检查、接口契约、多语言绑定生成
**Int ID的价值在运行时**：快速查找、零开销调度、确定性行为

---

## 📊 三种方案对比（更新版）

| 维度 | 纯Int ID | 纯WIT（运行时） | WIT→Int ID（编译时） |
|------|---------|----------------|---------------------|
| **性能** | ⚡ 极快 | 🐢 慢 | ⚡ 极快（编译时转换） |
| **类型安全** | ❌ 无 | ✅ 有 | ✅ 有 |
| **跨语言** | ❌ 困难 | ✅ 支持 | ✅ 支持（生成各语言绑定） |
| **接口文档** | ❌ 需手写 | ✅ WIT即文档 | ✅ WIT即文档 |
| **工具链复杂度** | 低 | 高 | 中（需代码生成器） |
| **生态兼容** | ❌ 无 | ✅ 标准 | ✅ 标准 |

**WIT→Int ID是两全其美的方案！**

## 🔧 技术实现：WIT → Int ID 的编译时转换

```moonbit
// 1. 定义WIT接口（开发者写）
// calculator.wit
interface calculator {
    add: func(a: u32, b: u32) -> u32;
    sub: func(a: u32, b: u32) -> u32;
}

// 2. 代码生成器自动产生（开发者看不到，但编译时生成）
// calculator_component.mbt (自动生成)
// 每个WIT函数被分配一个唯一的Int ID
const (
    FUNC_CALCULATOR_ADD = 1001
    FUNC_CALCULATOR_SUB = 1002
)

// 生成类型安全的包装器
pub fn add(a: U32, b: U32) -> U32!Error {
    // 内部用Int ID调用调度器
    let result = scheduler.call_component(
        FUNC_CALCULATOR_ADD,
        data_pack(a, b)
    )!
    data_unpack(result)
}

// 3. 调度器内部（纯Int ID，极快）
fn call_component(func_id: Int, data: Data) -> Result<Data, Error> {
    // Int ID查表，O(1)或更快
    let func_ptr = function_table[func_id]
    func_ptr(data)
}
```

**关键结论**：
> **WIT → Int ID是编译时转换，不是运行时转换。因此性能损失为零。**

生成的代码就是普通的函数调用 + Int ID查表，和手写Int ID没有本质区别。

## 🔮 演进路径（乐观更新版）

| 阶段 | 实现 | 性能 | 类型安全 | 说明 |
|------|------|------|---------|------|
| **MVP** | 手写Int ID | ⚡ | ❌ | 最快验证路径 |
| **V1** | 增加WIT解析器 + 代码生成器 | ⚡ | ✅ | 编译时转换，性能无损失 |
| **V2** | 生成的Int ID作为一等公民 | ⚡ | ✅ | 完善工具链 |

**好消息**：
> MVP阶段的手写Int ID代码，在V1阶段可以作为"WIT生成的Int ID代码"的直接替换——**接口层面兼容，底层都是Int ID**。

**没有技术债，只是"手写的"被"生成的"替代。**

---

## 💡 一多OS的独特优势

| 项目 | 方案 | 性能 |
|------|------|------|
| **Wasmtime原始调用** | 运行时WIT解析 | 中等 |
| **wRPC** | 网络RPC（序列化） | 较慢 |
| **一多OS（本方案）** | 编译时WIT→Int ID | 极快 |

> **一多OS的方案实际上是把"接口解析"从运行时前移到了编译时——这是Wasm组件模型中尚未被充分利用的优化空间。**

**一多OS的双轨制**：
- **对外**：讲WIT语言，融入Wasm生态
- **对内**：走Int ID高速路，保持极致性能
