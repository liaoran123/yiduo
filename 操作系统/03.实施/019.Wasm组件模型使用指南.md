# 一多 OS Wasm 组件模型使用指南

## 📋 概述

一多 OS 直接使用 Wasm 组件模型（WASI Preview 2 + WIT 接口）的现成功能，不需要自行设计能力发现机制。

---

## 🎯 核心原则

### 1. 完全使用 Wasm 组件模型现成功能
- ✅ WIT 接口定义
- ✅ 接口导入/导出
- ✅ 标准组件链接方式
- ❌ **不要**自行设计能力发现/能力字典

### 2. 固定组件 + ID 直接通信
- 配置文件固定定义组件
- 直接用 ID 通信
- 简单、直接、高效

### 3. 保留 capabilities 但只作为元数据
- 保留 `capabilities` 字段
- 仅用于记录组件能力（元数据）
- 不用来运行时发现

---

## 🏗️ Wasm 组件模型的标准做法

### WIT 接口定义示例

```wit
// 文件：interfaces/logger.wit
interface logger {
  write(level: string, message: string) -> result
  flush() -> result
}

// 文件：interfaces/counter.wit
interface counter {
  increment() -> u32
  decrement() -> u32
  get() -> u32
}
```

### 组件导出/导入示例

```wit
// 导出接口
world my-component {
  export logger
  export counter
}

// 导入接口
world my-app {
  import logger
  import counter
}
```

## 💻 一多 OS 简化方案

### 组件信息结构

```moonbit
struct ComponentInfo {
  name: String,                  // 组件名称
  component_type: String,        // wasm / native / native-core
  status: ComponentStatus,       // 组件状态
  capabilities: List<String>     // 元数据，记录能力，不用于发现！
}
```

### 通信方式：直接用 ID！

```moonbit
// ✅ 简单直接！不需要发现！
let logger_id = 1
let (s1, ok) = scheduler.send_small(from_id, logger_id, payload, priority)
```

---

## 📝 配置文件示例

```yaml
# components.yaml
components:
  - name: scheduler-core
    id: 0
    type: native-core
    capabilities: ["scheduling", "component-mgmt"]

  - name: logger
    id: 1
    type: wasm
    wit-interface: logger  # ← 指向 WIT 接口
    capabilities: ["log"]

  - name: counter
    id: 2
    type: wasm
    wit-interface: counter  # ← 指向 WIT 接口
    capabilities: ["count"]
```

---

## 🚀 总结

### 我们的方案：
1. ✅ **直接用 Wasm 组件模型现成功能**
2. ✅ **固定组件，直接用 ID 通信**
3. ✅ **capabilities 只作为元数据保留**
4. ❌ **不需要能力字典，不需要能力发现**

### 什么时候需要能力发现：
- 如果以后有搜索或 AI 功能再说
- 当前阶段不需要！
