# 一多 OS 自举闭环设计方案

## 核心问题：调度系统如何调度自己，形成完整闭环？

---

## 🏗️ 自举系统的架构层次

### 关键概念：特殊组件 vs 普通组件

```
一多 OS 组件层次
│
├── 🔧 **特殊组件（元组件）** - 调度系统本身
│   ├── 调度核心组件（负责调度所有组件）
│   ├── 配置加载组件（负责解析配置）
│   └── 组件加载器组件（负责加载组件）
│
└── 📦 **普通组件（功能组件）**
    ├── logger 组件（日志服务）
    ├── display 组件（显示服务）
    └── ...其他功能组件
```

---

## 🔄 完整自举闭环流程

### 阶段 1：预启动（极小核心）

#### 1.1 极小启动器

```
上电 → 极小启动器（只负责一件事）
        ↓
    初始化运行环境
        ↓
    启动调度核心组件
```

**极小启动器**：
- 不解析配置
- 不加载其他组件
- 只负责初始化调度核心

#### 1.2 调度核心的特殊性

调度核心是一个特殊组件，但它遵循相同的接口规范：

```moonbit
// 调度核心的"内部API"
struct SchedulerCore {
    // 它本身也是一个 ComponentInfo
    // name: "scheduler-core"
    // capabilities: ["scheduling", "component-mgmt", "message-dispatch"]
}

// 它能调度其他组件，也能调度自己（通过优先级控制）
```

---

### 阶段 2：自举启动（调度核心加载自己）

#### 2.1 完整自举流程

```
极小启动器
    ↓
初始化调度核心（特殊组件）
    ↓
调度核心"注册自己"为第一个组件
    ↓
调度核心加载"配置加载组件"（第二个组件）
    ↓
配置加载组件读取并解析配置
    ↓
配置加载组件把配置信息发回给调度核心
    ↓
调度核心加载"组件加载器组件"（第三个组件）
    ↓
调度核心通过配置驱动加载其他普通组件
    ↓
所有组件注册，形成完整闭环
```

#### 2.2 关键设计：自举钩子

调度核心预留自举钩子，在特定阶段调用特定组件：

```
调度核心启动
    ↓
[自举阶段1] 加载配置组件
    ↓
[自举阶段2] 读取配置
    ↓
[自举阶段3] 加载加载器组件
    ↓
[自举阶段4] 加载普通组件
    ↓
[运行阶段] 正常调度循环
```

---

## 🔧 自举闭环的关键机制

### 机制 1：调度核心的自识别

调度核心把自己注册为一个特殊组件：

```moonbit
// 在 scheduler.mbt 中
let self_component = ComponentInfo {
    name: "scheduler-core",
    component_type: "native-core",
    status: Created,
    capabilities: [
        "scheduling",      // 调度能力
        "component-mgmt",  // 组件管理
        "message-dispatch" // 消息分发
    ]
}

// 调度核心注册自己
let (mut scheduler, self_id) = scheduler.register(self_component)
```

**关键**：调度核心知道自己的ID，在消息处理中可以识别自己的消息。

---

### 机制 2：自举阶段控制

调度核心在不同阶段使用不同的优先级队列：

```
阶段 0：启动中 → 只处理自举相关消息（高优先级队列）
阶段 1：加载中 → 处理配置加载消息
阶段 2：运行中 → 正常调度所有组件
```

---

### 机制 3：配置驱动的自举配置

```yaml
# bootstrap-config.yaml - 自举配置
bootstrap:
  phases:
    phase-0:
      name: "core-init"
      components:
        - name: "scheduler-core"
          type: "native-core"

    phase-1:
      name: "config-loading"
      components:
        - name: "config-loader"
          type: "native"

    phase-2:
      name: "component-loading"
      components:
        - name: "component-loader"
          type: "native"
        - name: "file-system"
          type: "native"

    phase-3:
      name: "normal"
      components:
        - name: "logger"
          type: "wasm"
        - name: "display"
          type: "wasm"
```

## 📋 完整自举调用链示例

### 从用户视角：运行一个独立组件

```
用户想运行 "logger" 组件
    ↓
第1步：极小启动器运行，初始化调度核心
    ↓
第2步：调度核心自注册为 "scheduler-core" 组件 (ID=0)
    ↓
第3步：调度核心加载 "config-loader" 组件 (ID=1)
    ↓
第4步：调度核心向 config-loader 发送 "load-config" 消息
    ↓
第5步：config-loader 读取并解析配置，返回给调度核心
    ↓
第6步：调度核心加载 "component-loader" 组件 (ID=2)
    ↓
第7步：调度核心通过配置信息，加载 "logger" 组件 (ID=3)
    ↓
第8步：logger 组件注册，初始化
    ↓
第9步：调度核心向 logger 发送 "start" 消息
    ↓
第10步：logger 组件开始运行
    ↓
第11步：logger 可以向调度核心发送消息（调度自己！）
    ↓
第12步：形成完整闭环，logger 在调度系统下正常运行
```

## 🔄 自举闭环中的调度循环

### 关键代码概念

```moonbit
// bootstrap.mbt - 修改为自举版本

fn main() {
    // 第0阶段：极小启动
    println("Phase 0: Bootstrap core");
    let mut scheduler = scheduler.create();
    
    // 调度核心自注册
    let self_info = ComponentInfo {
        name: "scheduler-core",
        component_type: "native-core",
        status: Created,
        capabilities: ["scheduling", "component-mgmt", "message-dispatch"]
    };
    let (s1, self_id) = scheduler.register(self_info);
    scheduler = s1;
    println("Self-registered as component ID: " + self_id.to_string());
    
    // 第1阶段：加载配置组件
    println("Phase 1: Loading config loader");
    let config_loader_info = ComponentInfo {
        name: "config-loader",
        component_type: "native",
        status: Created,
        capabilities: ["config-parse"]
    };
    let (s2, config_loader_id) = scheduler.register(config_loader_info);
    scheduler = s2;
    
    // 第2阶段：发送加载配置消息（给配置加载器）
    println("Phase 2: Sending load-config message");
    let load_config_msg = create_small_message(
        from_id: self_id,
        to_id: config_loader_id,
        payload: SmallPayload {
            msg_type: 1,  // 约定：1 = 加载配置
            data: [ ... ] // 可以包含配置路径
        }
    );
    let (s3, _ok) = scheduler.send_small(
        from: self_id,
        to: config_loader_id,
        payload: ...,
        priority: High
    );
    scheduler = s3;
    
    // 第3阶段：调度循环处理自举消息
    println("Phase 3: Running bootstrap cycles");
    let mut s = scheduler;
    for i in 0 to 50 {  // 先运行几次自举循环
        s = s.process_one();  // 处理配置加载器的响应
    }
    scheduler = s;
    
    // 第4阶段：通过配置加载更多组件
    // 配置加载器会返回配置信息，驱动后续加载
    // ...
    
    // 第5阶段：进入正常调度循环
    println("Phase 5: Entering normal loop");
    let final_scheduler = scheduler.run_loop(1000);
    
    // 完成
    println("Bootstrap complete");
}
```

## 🔑 自举闭环的关键设计要素

### 1. 调度核心的自我识别

- 调度核心知道自己的组件ID
- 可以处理来自/去往自己的消息
- 不会死循环（通过优先级和消息类型控制）

### 2. 阶段化调度

- 自举阶段：只处理高优先级的自举消息
- 正常阶段：处理所有组件的消息
- 可以平滑过渡

### 3. 特殊钩子消息

- `LoadConfig` - 加载配置
- `LoadComponent` - 加载组件
- `PhaseTransition` - 阶段转换
- 这些是调度核心能识别的特殊消息类型

### 4. 最小假设，最大灵活

- 极小启动器只做最少的事
- 一切复杂逻辑都交给组件
- 配置驱动所有行为
