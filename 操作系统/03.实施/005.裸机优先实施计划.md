# 一多 OS 裸机优先实施计划

**核心原则：一多 OS 从第一天起就是裸机运行的真正操作系统**

---

## 🎯 核心理念

| 原则 | 说明 |
|------|------|
| **裸机优先** | 不依赖 Linux/Windows，从一开始就在裸机上运行 |
| **最小内核** | 先实现最小可运行内核，再逐步扩展功能 |
| **配置驱动** | 内核启动后通过配置文件加载组件来扩展 |
| **混合架构** | 内核关键部分用 MoonBit Native，HAL 层用 Rust/C |

---

## 🚀 详细计划：阶段 0 - 最小内核（优先！）

### T0.1：环境搭建（2 天）

**目标**：可以编译 MoonBit 到 ESP32-C3 并运行

**步骤**：
1. 安装 ESP-IDF
2. 安装 MoonBit 工具链
3. 验证 moonbit-esp32 示例
4. 运行官方的 Hello World 示例

**验证标准**：
- ESP32-C3 开发板可以烧录
- 可以通过 UART 看到输出

**参考**：
- [MoonBit on ESP32](https://www.moonbitlang.com/blog/moonbit-esp32)
- [moonbit-esp32 GitHub](https://github.com/moonbit-community/moonbit-esp32)

---

### T0.2：启动引导代码（3 天）

**目标**：上电复位 → 引导代码 → MoonBit main()

**利用 ESP-IDF 的启动流程**：
- ESP-IDF 已经有完整的 bootloader
- 我们只需要适配 MoonBit

**步骤**：
1. 研究 ESP-IDF 启动流程
2. 创建适配层，让 ESP-IDF 启动 MoonBit
3. 验证可以跳转到 MoonBit 代码

**文件结构**：
```
yiduo-kernel/
├── boot/               # 启动相关
│   └── esp-idf-adapter/
├── moonbit/            # MoonBit 内核代码
└── hal/                # Rust/C HAL 层
```

---

### T0.3：最小硬件初始化（3 天）

**目标**：
- 时钟初始化
- 内存初始化
- UART 初始化（用于调试）

**实现方式**：
- Rust/C 代码（利用 esp-hal）
- 导出为 C ABI
- MoonBit 通过 FFI 调用

**FFI 接口示例**：
```moonbit
// MoonBit 端
extern "C" fn hal_init() -> Int = "hal_init"
extern "C" fn hal_uart_send(byte: Byte) -> Unit = "hal_uart_send"
```

```rust
// Rust 端
#[no_mangle]
pub extern "C" fn hal_init() -> i32 {
    // 初始化时钟、内存、UART
    0
}

#[no_mangle]
pub extern "C" fn hal_uart_send(byte: u8) {
    // 发送字节到 UART
}
```

---

### T0.8：完整启动流程测试（3 天）

**完整启动流程**：
```
1. CPU 上电复位
   ↓
2. ESP-IDF bootloader
   ↓
3. Hal 初始化（Rust/C）
   ↓
4. MoonBit 运行时初始化
   ↓
5. 调用 MoonBit main()
   ↓
6. 从 Flash 读取配置
   ↓
7. 初始化调度器
   ↓
8. 启动调度循环
   ↓
9. UART 输出："一多 OS 启动成功！"
```

## 📂 建议的项目结构

```

├── src/                    # MoonBit 内核代码（已存在）
│   ├── scheduler/
│   ├── core/

│   ├── boot/               # 启动代码

│   └── moonbit-adapter/    # MoonBit ↔ HAL 桥接

├── interfaces/             # WIT 接口
└── 操作系统/               # 文档
```
