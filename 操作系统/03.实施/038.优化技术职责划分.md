# 一多OS优化技术职责划分

分析哪些优化技术应该在调度系统实现，哪些应该是独立组件。

---

## 📋 核心划分原则

| 判定标准 | 属于调度系统 | 属于独立组件 |
|---------|------------|------------|
| **职责** | 调度决策、消息路由、协调管理 | 特定功能、特定硬件、工具链 |
| **位置** | `src/scheduler/` 目录 | `src/core/`、`src/runtime/` 等目录 |
| **依赖** | 依赖整个系统状态 | 可独立演进 |

## 🎯 调度系统的职责（从035看）

调度系统只做这几件事：

1. ✅ **调度决策** - 分域调度、亲和调度、语义调度
2. ✅ **消息路由** - 零拷贝链式通信
3. ✅ **事件记录** - 确定性重放
4. ✅ **协调管理** - 决定组件下沉、资源分配

调度系统不做：
- ❌ 内存管理（全局内存池是独立组件）
- ❌ 编译器优化（LTO是工具链）
- ❌ 具体功能实现（AI推理、DPU驱动是组件）

## 🔍 澄清：运行时Int ID vs 编译时Int ID绑定

### 重要区别：

| 方面 | 编译时Int ID绑定（原037说法） | 运行时Int ID（实际实现） |
|------|----------------------------|------------------------|
| **绑定时机** | 编译时固定 | 运行时动态分配 |
| **是否适用于动态调度** | ❌ 不适用 | ✅ 适用 |
| **实际实现** | 不存在的 | 存在（`scheduler.register()`） |

### 实际代码验证：

看当前 `scheduler.mbt`：
- ✅ `register()` 函数在运行时动态分配 Int ID
- ✅ 使用 `FixedArray[Option[ComponentInfo]]` 按索引访问
- ✅ 消息里的 `from/to` 都是 Int，不是 String

### 结论：

**调度系统是动态的，所以用"运行时Int ID"，而不是"编译时Int ID绑定"**。

## 💡 关键结论

1. **调度系统是"大脑"**，负责决策和协调
2. **其他是"器官"**，独立实现特定功能
3. **工具链是"工具箱"**，编译时优化
4. **职责清晰**，各自独立演进

这样划分符合035文档的"管血液，不管器官"原则！
