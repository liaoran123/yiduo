# 移除能力发现功能总结

## 概述

本次工作移除了 `capabilities` 字段和能力发现功能，简化了一多 OS 架构。

---

## 修改内容

### 1. 调度器代码 (`scheduler.mbt`)
- ❌ **移除**：`ComponentInfo` 结构体中的 `capabilities` 字段
- ❌ **移除**：`has_capability()` 函数
- ❌ **移除**：`find_component_by_capability()` 函数
- ❌ **移除**：`find_all_components_by_capability()` 函数
- ❌ **移除**：`send_by_capability()` 函数
- ❌ **移除**：`list_contains()` 辅助函数
- ❌ **移除**：`list_reverse()` 辅助函数
- ✅ **保留**：核心调度功能
- ✅ **保留**：Int ID 索引优化
- ✅ **保留**：消息传递系统

### 2. 配置加载器 (`config_loader.mbt`)
- ❌ **移除**：`ComponentConfig` 结构体中的 `capabilities` 字段
- ❌ **移除**：`BOOTSTRAP_CONFIG_TEXT` 中的能力配置
- ✅ **保留**：配置解析功能

### 3. 自举入口 (`bootstrap.mbt`)
- ✅ **更新**：组件注册代码，移除 `capabilities`
- ✅ **更新**：简化测试逻辑

### 4. 文档
- ✅ **更新**：`008.组件配置格式规范.md` - 添加变更说明
- ✅ **新增**：本文档 - 总结工作内容

---

## 新架构

### 通信方式
- ✅ **直接使用 ID 通信**：组件之间通过固定 ID 发送消息
- ✅ **配置文件分配 ID**：启动时按配置顺序分配 ID
- ✅ **系统契约**：`ID 0` 永远是调度核心

### 简化架构图
```
┌─────────────────────────────────────────┐
│         配置文件 (固定 ID 分配)         │
│  - ID 0: scheduler-core                │
│  - ID 1: logger                        │
│  - ID 2: counter                       │
│  - ID 3: display                       │
└──────────────┬──────────────────────────┘
               │
               ↓
┌─────────────────────────────────────────┐
│          调度器 (Int ID 索引)           │
│  直接通过 ID 查找组件，无哈希开销       │
└─────────────────────────────────────────┘
```

---

## 优势

1. **更简单**：移除了不必要的复杂性
2. **更高效**：Int ID 直接索引，无需查找
3. **更符合当前阶段**：自举验证阶段不需要复杂机制
4. **Wasm 组件模型**：接口匹配已有 Wasm 组件模型处理

---

## 核心不需要，用户态可以做

### 调度系统核心
- ❌ **永久移除**：调度器核心不包含能力发现（避免影响性能）
- ✅ **保持简单高效**：核心调度功能尽可能轻量

### 用户态可以实现（如果需要）
如果用户真的需要能力发现，可以：
- ✅ **开发一个独立组件**来实现
- ✅ **通过 WIT 接口**提供能力查询服务
- ✅ **不影响调度核心**：作为可选的上层功能

### 设计理念
这符合一多 OS 的设计理念：
- **核心系统**：轻量、高效、稳定
- **高级功能**：通过组件灵活扩展，不污染核心
