## 📋 技术可行性证据

### 1. MoonBit 原生支持裸机运行

**证据来源：** [MoonBit Native on ESP32-C3: With C-Level Performance](https://www.moonbitlang.com/blog/moonbit-esp32)

**关键点：**
- ✅ **MoonBit Native backend** 可以直接编译到机器码，无需 Wasm 虚拟机
- ✅ 已在 **ESP32-C3** 上成功运行，性能达到 C 语言级别
- ✅ 有官方的 `moonbit-esp32` 绑定包，提供硬件访问接口
- ✅ 支持 GPIO、SPI、LCD、任务管理等硬件外设

**实际项目示例：**
- Game of Life 在 ESP32-C3 上运行
- 使用 240×240 LCD 屏幕
- MoonBit 代码直接编译为原生代码

---

### 2. Wasm 在裸机上的成熟生态

**证据来源：**
- [WebAssembly for Embedded Systems (Part 2)](https://bitsilica.com/embedded-webassembly-part-2/)
- [Wasm3 GitHub](https://github.com/wasm3/wasm3)
- [WebAssembly on Resource-Constrained IoT Devices](https://arxiv.org/pdf/2512.00035v1)

| 运行时 | 内存占用 | 支持平台 | 特点 |
|--------|----------|----------|------|
| **WAMR** | 50–80 KB | ESP32, STM32, 裸机 | 最成熟，支持 AOT 编译 |
| **Wasm3** | ~60 KB | ESP32, STM32, Arduino | 超快速解释器 |
| **WasmEdge** | 2–4 MB | Linux 嵌入式 | 适合 AI 和网络 |

**关键事实：**
- ✅ WAMR 支持**真正的裸机运行**
- ✅ Wasm3 已在 ESP32、STM32 等多种 MCU 上验证
- ✅ 学术研究表明，Wasm 在资源受限设备上性能可接受
- ✅ 即使是 50-80 KB 的运行时，对现代 MCU 来说完全没问题

---

### 3. FFI 桥接：MoonBit 可以调用任意 C/Rust 代码

**证据来源：** [A Guide to MoonBit C FFI](https://www.moonbitlang.com/pearls/moonbit-cffi)

**关键点：**
- ✅ MoonBit 支持完整的 `extern "C"` FFI
- ✅ Rust 可以导出 C ABI，MoonBit 可以调用
- ✅ 即使 MoonBit 生态不支持某个硬件，也可以用 Rust/C 写驱动
- ✅ 硬件抽象层用 Rust/C，调度核心用 MoonBit，完美结合

### FFI 桥接示例

即使 MoonBit 生态不支持某个硬件，我们依然可以：

```moonbit
// MoonBit 调度核心（不用改！）
extern "C" fn hardware_init() -> Int = "hardware_init"
extern "C" fn uart_send_byte(byte: Byte) -> Unit = "uart_send_byte"
extern "C" fn flash_read(addr: Int, buf: FixedArray[Byte], len: Int) -> Int = "flash_read"
```

```rust
// Rust 端（导出 C ABI，利用 Rust 生态）
#[no_mangle]
pub extern "C" fn hardware_init() -> i32 {
    // Rust 硬件初始化代码，使用 esp-hal
    0
}

#[no_mangle]
pub extern "C" fn uart_send_byte(byte: u8) {
    // Rust 发送字节到串口
}
```

### 阶段 1：加载基础组件（依然裸机）

一多 OS 已经在裸机上运行了，现在通过配置加载更多组件：

```yaml
# bootstrap_phase1.yaml (存储在 Flash 中)
apiVersion: yiduo.dev/v1alpha1
kind: System
spec:
  components:
    # Flash 驱动组件（替换简单的存储访问）
    - name: flash_storage
      type: native
      path: /flash/components/storage.wasm
    
    # 文件系统组件（构建在 Flash 之上）
    - name: littlefs
      type: wasm
      path: /flash/components/fs.wasm
      requires: flash_storage
```

**一多 OS 做的事情（在裸机上）：**
1. 从 Flash 读取配置
2. 加载这些组件
3. 系统功能增强了！

**内容：**
1. ✅ 集成 WAMR 或 Wasm3 运行时（作为 Native 组件）
2. ✅ Flash 驱动（Native，直接访问硬件）
3. ✅ 简单文件系统（Wasm 组件）
4. ✅ 从配置文件加载组件的完整流程

**组件加载流程：**
```
上电启动 → 内核初始化 → 读取配置 → 加载 Wasm 运行时 → 加载其他 Wasm 组件 → 系统运行
```

**证据：** WAMR/Wasm3 已在 ESP32 上验证可行！

## 💻 启动流程（真正的裸机）

```
1. CPU 上电复位
   ↓
2. 执行启动引导代码（汇编）
   - 初始化堆栈
   - 配置时钟
   - 初始化 RAM
   ↓
3. 跳转到 C/Rust 入口点
   - 初始化硬件
   - 初始化 MoonBit 运行时
   ↓
4. 调用 MoonBit 的 main()
   - 这是一多 OS 的入口！
   ↓
5. 从 Flash 读取 bootstrap.yaml
   ↓
6. 加载配置中的组件
   ↓
7. 启动调度循环
   ↓
8. 一多 OS 运行中！
```

```
写引导代码 → 写内核 → 写驱动 → 写文件系统 → 写应用 → 编译 → 烧录 → 测试

```
