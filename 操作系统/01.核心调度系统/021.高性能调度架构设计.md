# 一多 OS 高性能调度系统架构设计

## 📊 核心问题分析

一多 OS 的调度系统是核心瓶颈，所有组件通信都需经过它。我们需要在以下维度平衡：

| 维度 | 需求 | 裸机环境特点 |
|------|------|--------------|
| **性能** | 低延迟、高吞吐 | MCU 资源有限，主频 80-240MHz |
| **安全性** | 组件隔离 | Wasm 沙箱天然隔离 |
| **易用性** | 配置驱动 | 一多哲学核心 |
| **可扩展** | 多架构支持 | ESP32 → RISC-V → ARM → x86 |

## 📋 三种通信模式对比

### 1️⃣ 小消息：复制模式（安全优先）

**适用场景：**
- 配置命令
- 事件通知
- 控制信号
- 小数据包 (< 256 字节)

**特点：**
- ✅ 完全 Wasm 沙箱隔离
- ✅ 内存安全，无需生命周期管理
- ✅ 实现简单
- ❌ 有复制开销

**性能：**
- ESP32: ~1-5 μs (256 字节复制)

**MoonBit 示例：**
```moonbit
// 定义小消息结构
struct Message {
  type: MessageType,
  payload: Payload,
}

enum MessageType {
  Command,
  Event,
  Response,
}

struct Payload {
  // 小载荷内联
  data: List<Byte>,
  size: Int,
}

// 调度核心发送消息
fn send_small_message(target: ComponentId, msg: Message) -> Result<Unit, Error> {
  // 直接复制到消息队列
  queue_copy_send(target, msg)
}
```

### 2️⃣ 中消息：共享缓冲区 + 句柄模式（平衡）

**适用场景：**
- 传感器数据流
- 网络数据包
- 中等大小的处理块 (256B - 64KB)

**特点：**
- ✅ 零拷贝性能
- ✅ 内存池管理，避免碎片
- ⚠️ 需要生命周期管理
- ⚠️ Wasm 组件只能通过句柄访问，不能直接访问物理地址

**性能：**
- ESP32: ~0.1-0.5 μs (句柄传递)

**架构图：**
```
Wasm 组件 A (发送方)
    │
    │ 1. 请求分配缓冲区
    ▼
调度核心
    │
    │ 2. 从内存池分配
    ▼
共享内存区域 (非 Wasm 线性内存)
    │
    │ 3. 复制数据 (仅一次)
    ▼
Wasm 组件 B (接收方)
    │
    │ 4. 通过句柄访问
    ▼
调度核心
    │
    │ 5. 释放回内存池
    ▼
共享内存区域
```

**MoonBit 示例（优化版，Int ID + FixedArray）：**
```moonbit
// 内存池管理（优化：Int ID + FixedArray + 栈分配）
struct MemoryBlock {
  size: Int
  ref_count: Int
  is_free: Bool
}

struct MemoryPool {
  blocks: FixedArray[MemoryBlock]    // 直接索引，无哈希
  free_stack: FixedArray[Int]        // 空闲块索引栈
  free_top: Int                      // 栈顶指针
}

// 创建内存池（启动时预分配）
fn create(config: MemoryPoolConfig) -> MemoryPool {
  let block = MemoryBlock::{size: config.block_size, ref_count: 0, is_free: true}
  let blocks = FixedArray::make(config.block_count, block)
  let mut free_stack = FixedArray::make(config.block_count, 0)
  let mut i = 0
  while i < config.block_count {
    free_stack[i] = config.block_count - 1 - i
    i = i + 1
  }
  MemoryPool::{blocks: blocks, free_stack: free_stack, free_top: config.block_count}
}

// 分配（O(1)，栈pop，~5ns）
fn allocate(self: MemoryPool) -> (MemoryPool, Option[Int]) {
  if self.free_top <= 0 { return (self, None) }
  let new_top = self.free_top - 1
  let id = self.free_stack[new_top]
  let mut new_blocks = self.blocks
  new_blocks[id] = MemoryBlock::{size: new_blocks[id].size, ref_count: 1, is_free: false}
  (MemoryPool::{blocks: new_blocks, free_stack: self.free_stack, free_top: new_top}, Some(id))
}

// 发送方 API
fn send_medium(scheduler: Scheduler, from: Int, to: Int, handle: Int, priority: MessagePriority
) -> (Scheduler, Bool)
```

### 3️⃣ 大消息：共享内存 + 会话模式（性能优先）

## 🚀 RTOS 零拷贝消息队列实现

### 核心数据结构 (Rust)

```rust
// 零拷贝环形队列
struct RingBuffer<T> {
    buffer: *mut T,
    capacity: usize,
    read_idx: usize,
    write_idx: usize,
    // 原子计数器
    count: core::sync::atomic::AtomicUsize,
}

// 消息类型 (包含指针或小数据)
enum Message {
    // 小消息: 内联数据
    Small([u8; 256]),
    // 中消息: 内存池句柄
    Medium(BufferHandle),
    // 大消息: 共享内存会话
    Large(SessionHandle),
}

// 消息队列 (FreeRTOS风格)
struct MessageQueue {
    // 用零拷贝方式存储指针
    queue: RingBuffer<Message>,
    // 等待任务列表
    waiters: List<TaskHandle>,
}

// 发送消息 (零拷贝)
fn send_zero_copy(queue: &mut MessageQueue, msg: Message) -> Result<(), Error> {
    // 对于中/大消息,只移动句柄,不复制数据
    queue.queue.push(msg)?;
    // 唤醒等待者
    wake_waiters(queue);
    Ok(())
}
```

### 性能优化点

1. **缓存友好的布局**
   - 按 CPU 缓存行对齐 (64 字节)
   - 避免伪共享

2. **批量处理**
   - 一次调度处理多个消息
   - 减少上下文切换

3. **无锁数据结构**
   - 读端无锁 (原子操作)
   - 写端最小化临界区

4. **内存池预分配**
   - 启动时预分配所有缓冲区
   - 避免运行时碎片

## 🎭 调度器设计

### 优先级调度 + 消息驱动

```moonbit
/// 调度器核心结构（优化版）
/// 组件表: FixedArray[Option[ComponentInfo]] (无哈希查找)
/// 队列: RingBuffer[Message] × 3 (无Option装箱)
/// 内存池: FixedArray[MemoryBlock] + 栈分配
struct Scheduler {
  high_queue: RingBuffer[Message]      // 高优先级队列 (64槽)
  normal_queue: RingBuffer[Message]    // 普通优先级队列 (256槽)
  low_queue: RingBuffer[Message]       // 低优先级队列 (128槽)
  pool: MemoryPool                      // 预分配内存池
  components: FixedArray[Option[ComponentInfo]]  // 组件表，Int索引
  max_components: Int
  is_running: Bool
}

// 处理一条消息（优先级顺序：高 > 普通 > 低）
fn process_one(self: Scheduler) -> Scheduler {
  // 1. 先高优先级
  let (hq, opt_msg) = dequeue(self.high_queue)
  match opt_msg {
    Some(m) => dispatch({ self with high_queue: hq }, m)
    None => {
      // 2. 再普通优先级
      let (nq, opt_msg2) = dequeue(self.normal_queue)
      match opt_msg2 {
        Some(m) => dispatch({ self with normal_queue: nq }, m)
        None => {
          // 3. 最后低优先级
          let (lq, opt_msg3) = dequeue(self.low_queue)
          match opt_msg3 {
            Some(m) => dispatch({ self with low_queue: lq }, m)
            None => self  // 无消息
          }
        }
      }
    }
  }
}

// 分发消息（Int ID直接索引 FixedArray，~2ns）
fn dispatch(self: Scheduler, msg: Message) -> Scheduler {
  let to_id = parse_to_id(msg)
  match self.components[to_id] {
    Some(comp) => { /* 处理消息 */ }
    None => { /* 组件未注册 */ }
  }
}
```

## 🎯 总结

**推荐架构：**
- **小消息** → 复制模式 (安全优先)
- **中消息** → 句柄模式 (平衡)
- **大消息** → 共享内存 (性能优先)
- **底层** → RTOS 零拷贝消息队列

**核心优势：**
1. ✅ **灵活性**: 根据场景选择最佳模式
2. ✅ **安全性**: Wasm 沙箱 + 能力模型
3. ✅ **高性能**: 零拷贝路径 + 批处理
4. ✅ **可扩展**: 逐步增加功能,不破坏已有设计
