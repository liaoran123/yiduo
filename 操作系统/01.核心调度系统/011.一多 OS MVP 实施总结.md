## 🏗️ 一多 OS 四层架构

### 整体架构设计

```
┌───────────────────────────────────────────────────────────────────────┐
│                        一多 OS                                    │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │  L1: 场景配置层 - 配置驱动应用组合                        │  │
│  │  SceneConfig struct - 返回配置数据                      │  │
│  └─────────────────────────────────────────────────────────────┘  │
│                          ↓ (传递配置)                                │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │  L2: 调度整合层 - 智能调度与策略选择                   │  │
│  │  Scheduler struct - 根据配置创建细胞                  │  │
│  └─────────────────────────────────────────────────────────────┘  │
│                          ↓ (传递细胞)                              │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │  L3: 计算细胞层 - 独立可组合组件                        │  │
│  │  CameraCell struct - 封装后端                          │  │
│  └─────────────────────────────────────────────────────────────┘  │
│                          ↓ (调用后端)                              │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │  L4: 后端适配器层 - 硬件/库适配                          │  │
│  │  MockCameraBackend struct - 具体实现                    │  │
│  └─────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────┘
```

## 💻 核心实现详解

### 第 1 层：场景配置层 (L1)

#### 核心功能：加载场景配置，返回配置数据

**实现代码：**

```moonbit
/// 场景配置
struct SceneConfig {
  name: String
}

fn load_scene_config(scene_name: String) -> SceneConfig {
  println("[L1] 加载场景: " + scene_name)
  if scene_name == "smart_camera" {
    println("[L1] 智能相机场景 - AI 监控")
  } else {
    println("[L1] 默认场景")
  }
  { name: scene_name }
}
```

**设计理念：**
- 返回结构化的配置数据
- 配置真正影响后续层的行为
- 数据流向的起点

---

### 第 2 层：调度整合层 (L2)

#### 核心功能：根据配置创建和调度细胞

**实现代码：**

```moonbit
/// 调度器
struct Scheduler {
  scene_name: String
}

fn scheduler_new(scene_name: String) -> Scheduler {
  println("[L2] 创建调度器，场景: " + scene_name)
  { scene_name: scene_name }
}

fn scheduler_create_cell(scheduler: Scheduler) -> CameraCell {
  println("[L2] 调度器创建细胞...")
  if scheduler.scene_name == "smart_camera" {
    camera_cell_new("camera-001")
  } else {
    camera_cell_new("camera-default")
  }
}
```

**设计理念：**
- 接收 L1 的配置数据
- 根据配置决定创建什么细胞
- 真正的调度逻辑

---

### 第 3 层：计算细胞层 (L3)

#### 核心功能：封装后端，提供组件接口

**实现代码：**

```moonbit
/// 相机细胞
struct CameraCell {
  backend: MockCameraBackend
  cell_id: String
}

fn camera_cell_new(cell_id: String) -> CameraCell {
  println("[L3] 创建细胞: " + cell_id)
  { backend: mock_camera_new(), cell_id: cell_id }
}

fn camera_cell_init(cell: CameraCell) -> CameraCell {
  println("[L3] 初始化细胞: " + cell.cell_id)
  mock_camera_init(cell.backend)
  cell
}

fn camera_cell_capture(cell: CameraCell) -> (String, CameraCell) {
  println("[L3] 细胞捕获: " + cell.cell_id)
  let (img, new_backend) = mock_camera_capture(cell.backend)
  (img, { backend: new_backend, cell_id: cell.cell_id })
}
```

**设计理念：**
- 封装 L4 的后端
- 管理组件状态
- 提供统一的组件接口

---

### 第 4 层：后端适配器层 (L4)

#### 核心功能：具体的后端实现

**实现代码：**

```moonbit
/// Mock 相机后端
struct MockCameraBackend {
  frame_count: Int
}

fn mock_camera_new() -> MockCameraBackend {
  { frame_count: 0 }
}

fn mock_camera_capture(backend: MockCameraBackend) -> (String, MockCameraBackend) {
  let new_count = backend.frame_count + 1
  println("[L4] Mock 捕获第 " + new_count.to_string() + " 帧")
  ("Mock 图像 " + new_count.to_string(), { frame_count: new_count })
}
```

**设计理念：**
- 具体的实现细节
- 状态管理
- 被 L3 层调用

## 💡 架构改进历程

### 之前的问题（感谢用户的质疑！）

| 问题 | 说明 |
|------|------|
| ❌ **只是顺序调用** | 没有数据在层间流动 |
| ❌ **没有真正的 struct** | 只是函数调用 |
| ❌ **配置不起作用** | 配置没有影响后续层 |

### 现在的改进

| 改进 | 说明 |
|------|------|
| ✅ **数据真正流动** | SceneConfig → Scheduler → CameraCell |
| ✅ **每层都有 struct** | 每个层都有自己的数据结构 |
| ✅ **配置真的起作用** | L1 的配置决定 L2 创建什么细胞 |
| ✅ **状态在传递** | 后端状态从 L4 传回 L3 |
