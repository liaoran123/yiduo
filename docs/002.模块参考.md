## 1. core 模块（核心基础包）

**位置**: [runtime/core/](../runtime/core/)

**职责**: 提供所有高性能基础设施，包括消息系统、环形队列、内存池、内存管理器

### 1.1 message.mbt · 消息系统（V2 更新）

**位置**: [runtime/core/message.mbt](../runtime/core/message.mbt)

**核心优化**: 使用 Int ID 替代 String，消除转换开销；集成句柄安全；新增 auto_free 选项

**类型**: `Message`（枚举，三种变体）

| 变体 | 模式 | 适用场景 |
|------|------|---------|
| `SmallMessage` | 复制 | 命令、事件（<256B） |
| `MediumMessage` | 句柄 | 传感器数据（256B-64KB） |
| `LargeMessage` | 共享内存 | 图像、大文件（>64KB） |

**优先级枚举**: `MessagePriority::{ High | Normal | Low }`

**访问模式**: `AccessMode::{ ReadOnly | ReadWrite }`

**核心数据结构（V2 更新）**:
```moonbit
enum Message {
  SmallMessage { from: Int, to: Int, payload: SmallPayload }
  MediumMessage { from: Int, to: Int, handle: Int, auto_free: Bool }
  LargeMessage { from: Int, to: Int, handle: Int, access_mode: AccessMode, auto_free: Bool }
}

struct SmallPayload {
  msg_type: Int,
  data: List[Byte]
}
```

**新增 V2 API**:
| 函数 | 说明 |
|------|------|
| `create_medium_message(from, to, handle, auto_free, mem_manager)` | 创建 MediumMessage 并进行句柄安全检查 |
| `create_large_message(from, to, handle, access_mode, auto_free, mem_manager)` | 创建 LargeMessage 并进行句柄安全检查 |
| `on_message_processed(msg, receiver_id, mem_manager)` | 处理消息后的句柄清理（所有权转移 + 自动释放） |

### 1.2 ring_buffer.mbt · 零拷贝环形队列

**位置**: [runtime/core/ring_buffer.mbt](../runtime/core/ring_buffer.mbt)

**核心优化**: 去掉 Option[T] 装箱，用 read/write 指针判断空满，消除每个槽位的标记位开销

**核心结构**: `RingBuffer[T]`（泛型）

| 字段 | 类型 | 说明 |
|------|------|------|
| `buffer` | `FixedArray[T]` | 裸数组（无 Option 装箱） |
| `capacity` | `Int` | 总容量（实际可用 capacity-1） |
| `read_idx` | `Int` | 读指针 |
| `write_idx` | `Int` | 写指针 |

**关键 API**:

| 函数 | 复杂度 | 说明 |
|------|--------|------|
| `create(capacity, default)` | O(n) | 预分配数组 |
| `enqueue(self, item)` | O(1) | 入队（满时返回 false） |
| `dequeue(self)` | O(1) | 出队（空时返回 None） |
| `peek(self)` | O(1) | 查看队首，不取出 |
| `length(self)` | O(1) | 当前长度 |
| `is_empty(self)` | O(1) | 判空 |
| `capacity(self)` | O(1) | 队列容量（capacity-1） |

**性能特点**:
- 无 Option 装箱，消除每个元素的标记位开销
- 通过 read/write 指针比较判空满
- 浪费一个槽位（容量 = capacity - 1）
- 零拷贝（只移动指针，不移动数据）

### 1.3 memory_pool.mbt · 预分配内存池

**位置**: [runtime/core/memory_pool.mbt](../runtime/core/memory_pool.mbt)

**核心优化**: Int 索引替代 String，FixedArray 替代 Map，消除哈希查找和内存分配

**核心结构**: `MemoryPool`

| 字段 | 类型 | 说明 |
|------|------|------|
| `blocks` | `FixedArray[MemoryBlock]` | 内存块数组 |
| `free_stack` | `FixedArray[Int]` | 空闲块索引栈 |
| `free_top` | `Int` | 栈顶指针 |
| `config` | `MemoryPoolConfig` | 内存池配置（块大小、块数量） |

**辅助结构**:

```moonbit
struct MemoryBlock {
  size: Int,           // 块大小
  ref_count: Int,      // 引用计数
  is_free: Bool        // 是否空闲
}

struct MemoryPoolConfig {
  block_size: Int,     // 单个块大小（默认 4096）
  block_count: Int     // 块数量（默认 64）
}
```

**关键 API**:

| 函数 | 复杂度 | 说明 |
|------|--------|------|
| `create(config)` | O(n) | 预分配所有块 |
| `allocate(self)` | O(1) | 从栈顶弹出，返回 Int ID |
| `allocate_size(self, size)` | O(1) | 分配指定大小（当前忽略，使用默认） |
| `retain(self, id)` | O(1) | 引用计数+1 |
| `release(self, id)` | O(1) | 引用计数-1，归零回收入栈 |
| `free_count(self)` | O(1) | 空闲块数量 |
| `allocated_count(self)` | O(1) | 已分配块数量 |
| `total_blocks(self)` | O(1) | 总块数 |

### 1.4 memory_manager.mbt · L2 层：组件间零拷贝传递

**位置**: [runtime/core/memory_manager.mbt](../runtime/core/memory_manager.mbt)

**定位**: 组件级内存管理新模型的 **L2 层原型**，负责组件间 owned-buffer 的句柄安全传递

**核心功能**: 句柄所有权追踪（L2 owned-buffer）、防止双重释放、越权释放检查、引用计数管理、所有权转移

**核心结构**: `MemoryManager`

| 字段 | 类型 | 说明 |
|------|------|------|
| `pool` | `MemoryPool` | 底层内存池 |
| `max_handles` | `Int` | 最大句柄数（默认 64） |
| `handle_table` | `FixedArray[Option[HandleInfo]]` | 句柄信息表 |
| `free_handle_ids` | `List[Int]` | 可复用的句柄 ID |
| `next_handle_id` | `Int` | 下一个新句柄 ID |

**辅助结构**:

```moonbit
struct HandleInfo {
  owner_id: Int,       // 哪个组件拥有这个句柄
  ref_count: Int,      // 引用计数
  size: Int,           // 内存大小
  is_valid: Bool,      // 是否有效（防止双重释放）
  mem_id: Int,         // 关联的内存池块 ID
}
```

**关键 API**:

| 函数 | 复杂度 | 说明 |
|------|--------|------|
| `create(pool_config, max_handles)` | O(n) | 创建内存管理器 |
| `allocate_handle(self, owner_id, size)` | O(1) | 分配句柄，返回 (MemoryManager, Option[Int]) |
| `retain_handle(self, handle_id, caller_id)` | O(1) | 增加引用计数（需要 caller_id 是所有者） |
| `free_handle(self, handle_id, caller_id)` | O(1) | 释放句柄（检查所有者和有效性） |
| `transfer_ownership(self, handle_id, from_id, to_id)` | O(1) | 转移句柄所有权 |
| `get_handle_info(self, handle_id)` | O(1) | 获取句柄信息（调试用） |
| `get_stats(self)` | O(1) | 获取统计信息 (已分配内存, 活跃句柄, 可复用 ID) |
| `print_status(self)` | O(1) | 打印内存管理器状态 |

## 2. scheduler 模块（调度系统 V2 更新）

**位置**: [runtime/scheduler/](../runtime/scheduler/)

**职责**: 消息路由、优先级调度、组件管理、亲和度追踪、批处理

**系统契约**:
- `SCHEDULER_CORE_ID = 0`（调度核心的固定 ID）
- 组件 ID 按注册顺序分配，从 1 开始

### 核心结构: `Scheduler`（双模运行时更新）

| 字段 | 类型 | 说明 |
|------|------|------|
| `high_queue` | `RingBuffer[Message]` | 高优先级队列（容量 65，实际 64 槽） |
| `normal_queue` | `RingBuffer[Message]` | 普通优先级队列（容量 257，实际 256 槽） |
| `low_queue` | `RingBuffer[Message]` | 低优先级队列（容量 129，实际 128 槽） |
| `pool` | `MemoryPool` | 预分配内存池（默认 64 块 × 4KB） |
| `mem_manager` | `MemoryManager` | 内存管理器（句柄安全） |
| `components` | `FixedArray[Option[ComponentInfo]]` | 组件表（32 槽） |
| `max_components` | `Int` | 最大组件数（默认 32） |
| `is_running` | `Bool` | 运行状态 |
| `batch_size` | `Int` | 批处理大小（默认 8） |
| `handlers` | `HandlerRegistry` | **双模运行时**：Native 组件处理器注册表 |
| `debug_log` | `Bool` | 调试日志开关（基准测试中关闭以减少开销） |

### ComponentInfo 结构（双模运行时更新）

```moonbit
struct ComponentInfo {
  name: String,           // 组件名称
  component_type: ComponentType, // Native | Wasm | MoonBit（双模枚举）
  status: ComponentStatus // Created | Running | Paused | Stopped | Failed
  last_comm_with: FixedArray[Int],  // 最近通信的 16 个组件 ID
  last_comm_count: FixedArray[Int]  // 对应的通信计数
}
```

### ComponentType 枚举（双模运行时）

```moonbit

```

| 函数 | 说明 |
|------|------|
| `ComponentType::native()` | 创建 Native 类型 |
| `ComponentType::wasm()` | 创建 Wasm 类型 |
| `ComponentType::moonbit()` | 创建 MoonBit 类型 |
| `ComponentType::to_string()` | 转字符串（"native"/"wasm"/"moonbit"） |

| `ComponentType::from_string(s)` | 从字符串解析（`Option[ComponentType]`） |

| `deallocate(self, comp_id)` | 释放 Wasm 组件资源 | `Unit` |

### 调度算法（V2 更新）

```
process_one():
  1. 尝试 dequeue high_queue
     → 有消息: dispatch()
     → 无消息: 继续
  2. 尝试 dequeue normal_queue
     → 有消息: dispatch()
     → 无消息: 继续
  3. 尝试 dequeue low_queue
     → 有消息: dispatch()
     → 无消息: 无操作

process_batch() (V2 新增):
  1. 循环 batch_size 次
  2. 每次调用 process_one()
  3. 减少调度开销
```

### 消息分发逻辑（V2 更新）

`dispatch()` 函数会：
1. 检查消息的 `to_id` 是否为调度核心自己（ID 0）
   - 如果是，调用 `handle_core_message()`
2. 检查 `to_id` 是否在有效范围内
3. 用 Int 索引直接访问 `FixedArray[Option[ComponentInfo]]`
4. 如果是 MediumMessage 或 LargeMessage：
   - 使用 MemoryManager.transfer_ownership() 转移所有权
   - 如果 auto_free=true，使用 MemoryManager.free_handle() 释放句柄

### 组件亲和度（V2 新增）

每次发送消息时，`update_affinity()` 会：
1. 检查发送者和接收者是否有效
2. 在发送者的 last_comm_with 数组中查找接收者
3. 如果找到，增加对应的计数
4. 如果没找到，找空槽或替换计数最小的记录
5. 可以使用 `get_affinity_top()` 获取与某个组件通信最频繁的组件

## 3. config 模块（配置解析 · 递归 YAML）

**位置**: [runtime/config/](../runtime/config/)

**职责**: 自举配置解析（递归 YAML 解析器）、组件配置 CRUD 操作、热更新协调

**核心设计**:
- 使用递归 `YamlNode` 树状结构替代平面文本扫描
- `parse_yaml()` 返回嵌套的 YamlNode（支持 Scalar / Mapping / Seq）
- `ConfigManager` 提供配置文件的增删改查和变更监听
- `HotUpdateCoordinator` 监听配置变更并触发组件热更新

### 核心类型

| 类型 | 说明 |
|------|------|
| `YamlNode` | 递归 YAML 节点（Scalar/Mapping/Seq） |
| `ComponentDescriptor` | 组件描述符（从 YAML 反序列化） |
| `ConfigChange` | 配置变更记录（文件路径、类型、哈希） |
| `ChangeType` | 变更类型枚举（Created/Updated/Deleted） |
| `ConfigManager` | 配置管理器（CRUD + 监听器） |
| `HotUpdateConfig` | 热更新配置（启用/禁用、自动注册） |
| `HotUpdateResult` | 热更新结果（Success/Skipped/Failed） |

### 递归 YAML 解析器

```moonbit
pub enum YamlNode {
  YamlScalar(String)                    // 标量值
  YamlMapping(Array[(String, YamlNode)]) // 映射（递归）
  YamlSeq(Array[YamlNode])              // 序列（递归）
}

pub fn parse_yaml(content : String) -> Result[YamlNode, String]
```

辅助查询函数：

| 函数 | 说明 |
|------|------|
| `get_scalar(node, key)` | 获取 scalar 值 |
| `get_mapping(node, key)` | 获取子 mapping |
| `get_seq(node, key)` | 获取子 sequence |
| `seq_scalars(node)` | 遍历 seq 中的 scalar |
| `seq_mappings(node)` | 遍历 seq 中的 mapping |

### ConfigManager CRUD API

| 方法 | 说明 |
|------|------|
| `create_config(fs, file_name, content)` | 创建新配置文件 |
| `read_config(fs, file_name)` | 读取配置原始 YAML |
| `read_and_parse(fs, file_name)` | 读取并解析为 ComponentDescriptor |
| `write_config(fs, file_name, content)` | 写入/覆写配置文件 |
| `delete_config(fs, file_name)` | 删除配置文件 |
| `list_configs(fs)` | 列出配置目录下所有 YAML 文件 |

### 热更新 API

| 函数/方法 | 说明 |
|-----------|------|
| `apply_hot_update(change, fs, scheduler, mgr, config)` | 执行热更新（配置变更 → 组件重新加载） |
| `HotUpdateConfig::default()` | 默认热更新配置（启用、自动注册/停用） |

## 4. bootstrap 模块（启动器）

**位置**: [runtime/bootstrap.mbt](../runtime/bootstrap.mbt)

**职责**: 系统入口，初始化调度器，加载配置，注册组件

**核心设计**:
- 移除了能力发现
- 直接使用 Int ID 通信
- 配置驱动组件注册

### 启动流程

```
main()
 ├── [Step 1] 初始化调度器 V2
 │
 ├── [Step 2] 注册调度核心 (ID 0)
 │
 ├── [Step 3] 加载自举配置
 │
 ├── [Step 4] 配置驱动注册组件
 │   ├── 注册 logger (ID: 1)
 │   ├── 注册 counter (ID: 2)
 │   ├── 注册 display (ID: 3)
 │   └── ...
 │
 ├── [Step 5] 测试消息分发
 │   └── 发送测试消息给调度核心 (ID 0)
 │
 └── [Step 6] 运行调度循环 (迭代 5 次，批处理模式)
```

### 自举验证流程

自举验证版本（wasm-gc 目标）会：
1. 创建调度器 V2
2. 注册调度核心（ID 0）
3. 从内置字符串加载简化配置（wasm-gc 无文件系统）
4. 配置驱动注册其他组件
5. 发送测试消息给调度核心
6. 运行调度循环（批处理模式）
7. 打印最终状态（包括 MemoryManager 状态）

**native 目标**使用文件系统版 bootstrap：
- 读取 `configs/bootstrap.yaml` 确定运行时实现
- 通过递归 YAML 解析器读取组件配置
- 动态生成 `moon.pkg`（自举构建）
- 支持真实 WAMR 运行时链接

## 5. native_components 包（双模运行时）

### 说明

`native_components.mbt` 定义真实 Native 组件实现，展示如何通过 `ComponentType::Native` + `HandlerRegistry` 构建有状态的业务组件。这些组件直接在当前进程中执行（非沙箱），适用于高性能场景。

### CounterComponent（计数器组件）

```moonbit
pub struct CounterComponent {
  handler : @component.NativeMessageHandler  // 处理器函数
  get_count : () -> Int                      // 查询当前计数
  label : String                             // 组件名称
}
```

| 函数 | 说明 |
|------|------|
| `CounterComponent::create(label)` | 创建计数器，初始计数为 0 |
| `counter.handler` | 注册到 Scheduler 的 Native 处理器 |
| `(counter.get_count)()` | 查询当前消息计数 |
| `counter.create_component_info(type)` | 创建对应类型的 ComponentInfo |

**工作原理**：每次收到消息时内部计数器 +1，通过 `get_count` 闭包查询状态。

### AccumulatorComponent（累加器组件）

```moonbit
pub struct AccumulatorComponent {
  handler : @component.NativeMessageHandler  // 处理器函数
  get_total : () -> Int                      // 查询当前累加总和
  label : String                             // 组件名称
}
```

| 函数 | 说明 |
|------|------|
| `AccumulatorComponent::create(label)` | 创建累加器，初始总和为 0 |
| `acc.handler` | 注册到 Scheduler 的 Native 处理器 |
| `(acc.get_total)()` | 查询当前累加总和 |
| `acc.create_component_info(type)` | 创建对应类型的 ComponentInfo |

**工作原理**：每次收到消息时从 `payload.msg_type` 提取数值并累加，通过 `get_total` 闭包查询状态。

### 使用示例

```moonbit
let pool = @core.MemoryPool::create(@core.MemoryPoolConfig::create(4096, 64))
let mgr = @core.MemoryManager::create(pool, 64)
let scheduler = @scheduler.Scheduler::create_with_config(mgr, 8, 32)
let counter = CounterComponent::create("my-counter")
let (s1, comp_id) = scheduler.register(counter.create_component_info(@component.ComponentType::native()))
let s2 = s1.register_handler(comp_id, counter.handler)
// 发送消息触发处理
let (s3, _) = s2.send_small(0, comp_id, @core.SmallPayload::create(1, []), @core.MessagePriority::high())
let s4 = s3.process_one()
// (counter.get_count)() == 1
```
