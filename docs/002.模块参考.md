## 1. core 模块（核心基础包）

**位置**: [src/core/](../src/core/)

**职责**: 提供所有高性能基础设施

### 1.1 message.mbt · 消息系统

**位置**: [src/core/message.mbt](../src/core/message.mbt)

**核心优化**: 使用 Int ID 替代 String，消除转换开销

**类型**: `Message`（枚举，三种变体）

| 变体 | 模式 | 适用场景 |
|------|------|---------|
| `SmallMessage` | 复制 | 命令、事件（<256B） |
| `MediumMessage` | 句柄 | 传感器数据（256B-64KB） |
| `LargeMessage` | 共享内存 | 图像、大文件（>64KB） |

**优先级枚举**: `MessagePriority::{ High | Normal | Low }`

**访问模式**: `AccessMode::{ ReadOnly | ReadWrite }`

**核心数据结构**:
```moonbit
enum Message {
  SmallMessage { from: Int, to: Int, payload: SmallPayload }
  MediumMessage { from: Int, to: Int, handle: Int }
  LargeMessage { from: Int, to: Int, handle: Int, access_mode: AccessMode }
}

struct SmallPayload {
  msg_type: Int,
  data: List[Byte]
}
```

### 1.2 ring_buffer.mbt · 零拷贝环形队列

**位置**: [src/core/ring_buffer.mbt](../src/core/ring_buffer.mbt)

**核心优化**: 去掉 Option[T] 装箱，用 read/write 指针判断空满，消除每个槽位的标记位开销

**核心结构**: `RingBuffer[T]`（泛型）

| 字段 | 类型 | 说明 |
|------|------|------|
| `buffer` | `FixedArray[T]` | 裸数组（无 Option 装箱） |
| `capacity` | `Int` | 总容量（实际可用 capacity-1） |
| `read_idx` | `Int` | 读指针 |
| `write_idx` | `Int` | 写指针 |

**关键 API**:

| 函数 | 复杂度 | 说明 |
|------|--------|------|
| `create(capacity, default)` | O(n) | 预分配数组 |
| `enqueue(self, item)` | O(1) | 入队（满时返回 false） |
| `dequeue(self)` | O(1) | 出队（空时返回 None） |
| `peek(self)` | O(1) | 查看队首，不取出 |
| `length(self)` | O(1) | 当前长度 |
| `is_empty(self)` | O(1) | 判空 |
| `capacity(self)` | O(1) | 队列容量（capacity-1） |

**性能特点**:
- 无 Option 装箱，消除每个元素的标记位开销
- 通过 read/write 指针比较判空满
- 浪费一个槽位（容量 = capacity - 1）
- 零拷贝（只移动指针，不移动数据）

### 1.3 memory_pool.mbt · 预分配内存池

**位置**: [src/core/memory_pool.mbt](../src/core/memory_pool.mbt)

**核心优化**: Int 索引替代 String，FixedArray 替代 Map，消除哈希查找和内存分配

**核心结构**: `MemoryPool`

| 字段 | 类型 | 说明 |
|------|------|------|
| `blocks` | `FixedArray[MemoryBlock]` | 内存块数组 |
| `free_stack` | `FixedArray[Int]` | 空闲块索引栈 |
| `free_top` | `Int` | 栈顶指针 |
| `config` | `MemoryPoolConfig` | 内存池配置（块大小、块数量） |

**辅助结构**:

```moonbit
struct MemoryBlock {
  size: Int,           // 块大小
  ref_count: Int,      // 引用计数
  is_free: Bool        // 是否空闲
}

struct MemoryPoolConfig {
  block_size: Int,     // 单个块大小（默认 4096）
  block_count: Int     // 块数量（默认 64）
}
```

**关键 API**:

| 函数 | 复杂度 | 说明 |
|------|--------|------|
| `create(config)` | O(n) | 预分配所有块 |
| `allocate(self)` | O(1) | 从栈顶弹出，返回 Int ID |
| `allocate_size(self, size)` | O(1) | 分配指定大小（当前忽略，使用默认） |
| `retain(self, id)` | O(1) | 引用计数+1 |
| `release(self, id)` | O(1) | 引用计数-1，归零回收入栈 |
| `free_count(self)` | O(1) | 空闲块数量 |
| `allocated_count(self)` | O(1) | 已分配块数量 |
| `total_blocks(self)` | O(1) | 总块数 |

## 2. scheduler 模块（调度系统）

**位置**: [src/scheduler/](../src/scheduler/)

**职责**: 消息路由、优先级调度、组件管理

**系统契约**:
- `SCHEDULER_CORE_ID = 0`（调度核心的固定 ID）
- 组件 ID 按注册顺序分配，从 1 开始

### 核心结构: `Scheduler`

| 字段 | 类型 | 说明 |
|------|------|------|
| `high_queue` | `RingBuffer[Message]` | 高优先级队列（容量 65，实际 64 槽） |
| `normal_queue` | `RingBuffer[Message]` | 普通优先级队列（容量 257，实际 256 槽） |
| `low_queue` | `RingBuffer[Message]` | 低优先级队列（容量 129，实际 128 槽） |
| `pool` | `MemoryPool` | 预分配内存池（默认 64 块 × 4KB） |
| `components` | `FixedArray[Option[ComponentInfo]]` | 组件表（32 槽） |
| `max_components` | `Int` | 最大组件数（默认 32） |
| `is_running` | `Bool` | 运行状态 |

### ComponentInfo 结构

```moonbit
struct ComponentInfo {
  name: String,          // 组件名称
  component_type: String, // "native" | "wasm" | "moonbit"
  status: ComponentStatus // Created | Initialized | Running | Paused | Stopped | Error
}
```

### ComponentStatus 枚举

```moonbit
enum ComponentStatus {
  Created,      // 已创建
  Initialized,  // 已初始化
  Running,      // 运行中
  Paused,       // 已暂停
  Stopped,      // 已停止
  Error         // 错误
}
```

### 核心 API

| 函数 | 说明 | 返回值 |
|------|------|-------|
| `create()` | 创建调度器 | `Scheduler` |
| `register(self, info)` | 注册组件 | `(Scheduler, Int)` - 新调度器和分配的 ID |
| `send_small(self, from, to, payload, priority)` | 发小消息 | `(Scheduler, Bool)` - 是否成功 |
| `send_medium(self, from, to, handle, priority)` | 发中消息（句柄模式） | `(Scheduler, Bool)` - 是否成功 |
| `send_large(self, from, to, handle, access_mode, priority)` | 发大消息（共享内存） | `(Scheduler, Bool)` - 是否成功 |
| `send_message(self, from, to, msg, priority)` | 发送通用消息 | `(Scheduler, Bool)` - 是否成功 |
| `process_one(self)` | 处理一条消息 | `Scheduler` - 新调度器 |
| `dispatch(self, msg)` | 分发消息给目标组件 | `Scheduler` - 新调度器 |
| `handle_core_message(self, msg)` | 调度核心消息处理 | `Scheduler` - 新调度器 |
| `run_loop(self, max_iter)` | 运行调度循环 | `Scheduler` - 新调度器 |
| `print_status(self)` | 打印调度器状态 | `Unit` |
| `component_name(self, id)` | 获取组件名称 | `String` |
| `component_count(self)` | 获取组件数量 | `Int` |
| `get_component_info(self, id)` | 获取组件信息字符串 | `String` |
| `high_queue_length(self)` | 高优队列长度 | `Int` |
| `normal_queue_length(self)` | 普通队列长度 | `Int` |
| `low_queue_length(self)` | 低优队列长度 | `Int` |
| `pool_status(self)` | 内存池状态 | `(Int, Int)` - (空闲数, 已分配数) |

### 调度算法

```
process_one():
  1. 尝试 dequeue high_queue
     → 有消息: dispatch()
     → 无消息: 继续
  2. 尝试 dequeue normal_queue
     → 有消息: dispatch()
     → 无消息: 继续
  3. 尝试 dequeue low_queue
     → 有消息: dispatch()
     → 无消息: 无操作
```

### 消息分发逻辑

`dispatch()` 函数会：
1. 检查消息的 `to_id` 是否为调度核心自己（ID 0）
   - 如果是，调用 `handle_core_message()`
2. 检查 `to_id` 是否在有效范围内
3. 用 Int 索引直接访问 `FixedArray[Option[ComponentInfo]]`
4. 如果是 MediumMessage 或 LargeMessage，自动释放内存池块

## 3. config 模块（配置解析）

**位置**: [src/config/](../src/config/)

**职责**: 解析配置（自举验证使用内置字符串，完整版本支持 YAML/JSON）

**核心优化**: 移除了 capabilities 字段，简化配置结构

### 核心类型

| 类型 | 说明 |
|------|------|
| `AppConfig` | 完整应用配置 |
| `Metadata` | 元数据（名称、版本、描述） |
| `Spec` | 规格（组件列表） |
| `ComponentConfig` | 组件配置项 |
| `ConfigType` | 配置类型枚举（YAML/JSON） |

### ComponentConfig 结构（简化版）

```moonbit
struct ComponentConfig {
  name: String,
  component_type: String,
  description: Option[String],
  path: Option[String],
  required: Bool
}
```

### 关键 API

| 函数 | 说明 |
|------|------|
| `load(path)` | 加载配置文件（自动检测格式） |
| `parse_file(path, config_type)` | 解析配置文件 |
| `load_bootstrap()` | 加载自举配置（从内置字符串） |
| `parse_from_string(config_text)` | 从字符串解析配置（自举验证使用） |
| `validate(config)` | 验证配置完整性 |

## 4. bootstrap 模块（启动器）

**位置**: [src/bootstrap.mbt](../src/bootstrap.mbt)

**职责**: 系统入口，初始化调度器，加载配置，注册组件

**核心设计**:
- 移除了能力发现
- 直接使用 Int ID 通信
- 配置驱动组件注册

### 启动流程

```
main()
 ├── [Step 1] 初始化调度器
 │
 ├── [Step 2] 注册调度核心 (ID 0)
 │
 ├── [Step 3] 加载自举配置
 │
 ├── [Step 4] 配置驱动注册组件
 │   ├── 注册 logger (ID: 1)
 │   ├── 注册 counter (ID: 2)
 │   ├── 注册 display (ID: 3)
 │   └── ...
 │
 ├── [Step 5] 测试消息分发
 │   └── 发送测试消息给调度核心 (ID 0)
 │
 └── [Step 6] 运行调度循环 (迭代 5 次)
```

### 自举验证流程

自举验证版本会：
1. 创建调度器
2. 注册调度核心（ID 0）
3. 从内置字符串加载自举配置
4. 配置驱动注册其他组件
5. 发送测试消息给调度核心
6. 运行调度循环
7. 打印最终状态
