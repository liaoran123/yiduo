# 一多 OS 架构设计文档

## 核心架构：四元哲学

一多 OS 的设计围绕四个核心概念展开，每个概念对应具体的技术实现：

| 哲学概念 | 技术映射 | 代码实现 |
|---------|---------|---------|
| **意志（配置文件）** | 用户的声明式意图 | [内置自举配置](../src/config/config_loader.mbt#L68-L90) |
| **DNA（组件）** | 系统的基本单元 | [ComponentInfo](../src/scheduler/scheduler.mbt#L22-L26) |
| **树形（配置层级）** | 配置的层次结构 | [AppConfig → Spec → ComponentConfig](../src/config/config_loader.mbt#L33-L38) |
| **链式（组件通信）** | 组件间的消息传递 | [Message 三种模式（Int ID）](../src/core/message.mbt#L24-L45) |

## 核心数据结构

### 消息系统（三种模式，Int ID）

```
Message (enum)
 ├── SmallMessage { from: Int, to: Int, payload }   ← 复制模式（安全优先）
 │    适用: 配置命令、事件通知、控制信号
 │    优化: from/to 为 Int，无需字符串查找
 │
 ├── MediumMessage { from: Int, to: Int, handle }   ← 句柄模式（平衡）
 │    适用: 传感器数据、网络包
 │    优化: 只传递句柄（内存池索引），零拷贝
 │
 └── LargeMessage { from: Int, to: Int, handle, access_mode } ← 共享内存（性能优先）
      适用: 图像缓冲、大文件
      优化: 共享内存 + 访问模式控制
```

**核心优化**: 所有消息的 from/to 字段使用 Int ID 替代 String，消除转换开销

### 优先级队列

```
高优队列 (High Priority)   → 容量 64（RingBuffer 容量 65）
普通队列 (Normal Priority) → 容量 256（RingBuffer 容量 257）
低优队列 (Low Priority)    → 容量 128（RingBuffer 容量 129）
```

### 组件注册表

```
FixedArray[Option[ComponentInfo]] (32 槽位)
 ├── [0]: Some(ComponentInfo)  ← 调度核心 (native-core, ID: 0)
 ├── [1]: Some(ComponentInfo)  ← 日志服务 (native)
 ├── [2]: Some(ComponentInfo)  ← 计数器 (wasm)
 ├── [3]: Some(ComponentInfo)  ← 显示器 (wasm)
 ├── [4]: None                 ← 空闲
 └── ...
```

**系统契约**: ID 0 被调度核心占用，其他组件从 1 开始分配

## 性能架构

我们采用了三层性能优化策略：

### 第一层：语言层面（MoonBit 内置）

| 特性 | 说明 | 受益代码 |
|------|------|---------|
| **值类型** | 结构体存储在栈上，避免堆分配 | [MemoryBlock](../src/core/memory_pool.mbt#L6-L10)、[ComponentInfo](../src/scheduler/scheduler.mbt#L22-L26) |
| **Int ID 替代 String** | 栈上分配，比较只需一条指令 | [Message from/to](../src/core/message.mbt#L28-L44) |
| **Native 编译** | 直接编译为机器码，不需要 VM | 所有代码 |

### 第二层：数据结构优化（我们做的）

| 优化 | 前 | 后 | 提升 |
|------|---|----|------|
| **组件表** | `Map[String, ComponentInfo]` | `FixedArray[Option[ComponentInfo]]` | ~50x |
| **内存池** | `Map[String, MemoryBlock]` | `FixedArray[MemoryBlock]` + 栈 | ~10x |
| **环形队列** | `FixedArray[Option[T]]` | `FixedArray[T]` (无装箱) | ~4x |
| **消息 ID** | `String` 类型 | `Int` 类型 | ~50x |

### 第三层：混合架构（未来）

```
MoonBit 调度核心 (90% 代码，90% C 性能)
   +
 Rust/C 硬件驱动 (10% 代码，100% 性能)
   =
 整体 ~95% C 语言性能
```

## 数据流

### 启动流程（自举验证版）

```
main()
 ├── [Step 1] 初始化调度器
 │   ├── 创建 RingBuffer（高优 65/普通 257/低优 129）
 │   ├── 创建 MemoryPool（64 块 × 4KB）
 │   └── 创建组件表（32 槽位）
 │
 ├── [Step 2] 注册调度核心 (ID 0)
 │   └── 调度核心自注册，ID 固定为 0
 │
 ├── [Step 3] 加载自举配置
 │   └── 从内置字符串加载（简化版格式）
 │
 ├── [Step 4] 配置驱动注册组件
 │   ├── 注册 logger (ID: 1)
 │   ├── 注册 counter (ID: 2)
 │   ├── 注册 display (ID: 3)
 │   └── ...
 │
 ├── [Step 5] 测试消息分发
 │   └── 发送测试消息给调度核心 (ID 0)
 │
 └── [Step 6] 运行调度循环
       ├── dequeue(高优队列) → dispatch 或跳过
       ├── dequeue(普通队列) → dispatch 或跳过
       ├── dequeue(低优队列) → dispatch 或跳过
       └── 迭代完成后打印状态

消息生命周期:
  发送方 → enqueue → RingBuffer → dequeue → dispatch → 接收方
                                                    │
                                                release block (句柄模式)
```
