## 核心数据结构（V2 更新）

### 消息系统（三种模式，Int ID + 句柄安全）

```
Message (enum)
 ├── SmallMessage { from: Int, to: Int, payload }   ← 复制模式（安全优先）
 │    适用: 配置命令、事件通知、控制信号
 │    优化: from/to 为 Int，无需字符串查找
 │
 ├── MediumMessage { from: Int, to: Int, handle, auto_free } ← 句柄模式（零拷贝）
 │    适用: 传感器数据、网络包
 │    优化: 只传递句柄（内存管理器索引），零拷贝
 │    新增: auto_free 选项（接收后自动释放）
 │
 └── LargeMessage { from: Int, to: Int, handle, access_mode, auto_free } ← 共享内存
      适用: 图像缓冲、大文件
      优化: 共享内存 + 访问模式控制
```

**核心优化**: 
- 所有消息的 from/to 字段使用 Int ID 替代 String，消除转换开销
- MediumMessage 和 LargeMessage 新增 `auto_free` 选项
- 集成 MemoryManager 进行句柄安全管理

### 优先级队列

```
高优队列 (High Priority)   → 容量 64（RingBuffer 容量 65）
普通队列 (Normal Priority) → 容量 256（RingBuffer 容量 257）
低优队列 (Low Priority)    → 容量 128（RingBuffer 容量 129）
```

### 组件注册表（双模运行时更新）

```
FixedArray[Option[ComponentInfo]] (32 槽位)
 ├── [0]: Some(ComponentInfo)  ← 调度核心 (type: Native, ID: 0)
 │    新增: last_comm_with[16] (最近通信组件 ID)
 │    新增: last_comm_count[16] (通信计数)
 ├── [1]: Some(ComponentInfo)  ← 日志服务 (type: Native)
 ├── [2]: Some(ComponentInfo)  ← 计数器 (type: Wasm)
 ├── [3]: Some(ComponentInfo)  ← 显示器 (type: Wasm)
 ├── [4]: None                 ← 空闲
 └── ...
```

**系统契约**: ID 0 被调度核心占用，其他组件从 1 开始分配

### L2 层：组件间零拷贝传递（内存管理器）

当前 MemoryManager 作为[新模型](/操作系统/04.全局调度编排/006.组件级内存管理新模型.md) 的 **L2 层原型**已实现，负责组件间数据的句柄安全传递：

```
MemoryManager（L2 层：组件间 owned-buffer 协调）
 ├── pool: MemoryPool
 ├── max_handles: Int (64)
 ├── handle_table: FixedArray[Option[HandleInfo]]
 │    ├── owner_id: Int (哪个组件拥有)
 │    ├── ref_count: Int (引用计数)
 │    ├── size: Int (内存大小)
 │    ├── is_valid: Bool (是否有效，防双重释放)
 │    └── mem_id: Int (关联的内存池块 ID)
 ├── free_handle_ids: List[Int] (可复用句柄 ID)
 └── next_handle_id: Int (下一个新句柄 ID)
```

**核心功能**:
- 句柄所有权追踪（L2 owned-buffer 的所有者标记）
- 防止双重释放（is_valid 标记）
- 防止越权释放（检查 owner_id）
- 引用计数管理（多个读者共享句柄）
- 所有权转移（transfer_ownership）

**完整新模型层级**（[设计文档](/操作系统/04.全局调度编排/006.组件级内存管理新模型.md)）：

| 层级 | 职责 | 状态 |
|------|------|------|
| **L1** | 组件内 Arena 分配器（Wasm 线性内存内部自治） | 🟡 规划中，Wasm 运行时就绪后 |
| **L2** | 组件间 owned-buffer 零拷贝传递（当前 MemoryManager） | ✅ 已实现 |
| **L3** | 组件销毁回收（组件销毁 = 线性内存整体回收） | 🟡 规划中，component_manager 成熟后 |
| **L4** | 长周期组件周期性重启 | 🔵 远期

## 双模运行时架构（2026-05）

### 架构理念

一多 OS 支持**二元执行模式**：同一系统内 Native 组件和 Wasm 组件共存，通过 Scheduler 统一调度。

```
调度器核心 (ID: 0)
    │
    ├── dispatch(msg) ─── match component_type.to_int()
    │       │
    │       ├── 0 (Native)
    │       │   └── HandlerRegistry.invoke(comp_id, from_id, payload)
    │       │       └── 直接函数指针调用（~2ns，无序列化开销）
    │       │
    │       ├── 1 (Wasm)
    │       │   └── WasmRuntime.invoke(comp_id, from_id, payload)
    │       │       ├── ⚡ 模拟模式(L0)：NativeMessageHandler 同进程模拟
    │       │       ├── 🚀 真实模式(L1)：WasmRuntime 抽象接口
    │       │       └── 🔒 沙箱模式(L2)：外部 Wasm 运行时（FFI 绑定，预留）
    │       │
    │       └── 2 (MoonBit)
    │           └── （预留）接口
    │
    └── ComponentType 枚举确保类型安全
```

### ComponentType 枚举

```moonbit
pub enum ComponentType {
  Native   // 当前进程直接执行，通过 HandlerRegistry 调用
  Wasm     // 独立线性内存空间，沙箱隔离（预留）
  MoonBit  // 预留接口
}
```

- **Native**：适用于性能关键路径（日志服务、调度决策、计数器），绕过 Wasm 序列化/反序列化
- **Wasm**：适用于安全隔离场景（第三方插件、用户代码），独立内存空间
- **MoonBit**：预留，未来 MoonBit 原生组件

### HandlerRegistry（Native 执行引擎）

```moonbit
pub struct HandlerRegistry {
  handlers : FixedArray[@component.NativeMessageHandler?]
  max_handlers : Int
}
```

| 方法 | 功能 |
|------|------|
| `register_handler(comp_id, handler)` | 注册 Native 组件处理器 |
| `get_handler(comp_id)` | 获取组件处理器（Option） |
| `invoke(comp_id, from_id, payload)` | 调用处理器（Bool 表示是否存在） |
| `unregister(comp_id)` | 解注册处理器 |

处理器签名：`(comp_id: Int, from_id: Int, payload: SmallPayload) -> Unit`

### WasmRuntime（Wasm 执行引擎）

WasmRuntime 是 Wasm 组件的执行引擎抽象，通过函数表模式兼容 MoonBit 类型系统：

```moonbit
pub struct WasmRuntime {
  invoke     : (Int, Int, @core.SmallPayload) -> Unit  // 调用组件处理器
  register   : (Int, NativeMessageHandler) -> Unit      // 注册处理器（模拟模式）
  load       : (Int, Bytes) -> Result[Unit, String]     // 加载 Wasm 字节码
  deallocate : (Int) -> Unit                            // 释放组件资源
}
```

| 构造函数 | 说明 |
|---------|------|
| `WasmRuntime::create_simulated(max_handlers)` | 创建模拟运行时（同进程 Native 回调，用于开发/测试） |
| `WasmRuntime::from_fields(invoke, register, load, deallocate)` | 从函数表构造运行时实例（供外部包使用） |
| `create_wamr(max_components)` | 创建 WAMR 外部运行时（仅 native 目标，在 runtime/wamr 包中） |

#### 三层运行时演进

| 层 | 名称 | 实现 | 状态 |
|----|------|------|------|
| **L0** | 模拟运行时 | `create_simulated()` → NativeMessageHandler 回调 | ✅ 已实现 |
| **L1** | 接口抽象 | `WasmRuntime` 函数表定义 + Scheduler 集成 | ✅ 已实现 |
| **L2** | 外部运行时 | WAMR FFI 绑定（`runtime/wamr` 包，仅 native 目标） | ✅ 已实现（stub 模式） |

Scheduler 通过 `Option[WasmRuntime]` 持有运行时实例：`None`=Wasm 组件不可用，`Some(rt)`=通过 rt.invoke 执行。使用 `set_wasm_runtime(rt)` 方法注入：

```moonbit
let rt = @component.WasmRuntime::create_simulated(32)
let scheduler = scheduler.set_wasm_runtime(rt)
```

### 真实 Native 组件

CounterComponent（计数器）和 AccumulatorComponent（累加器）演示如何通过 Native 处理器构建有状态业务组件：

- 通过闭包捕获内部状态（计数、总和）
- 通过 `(component.get_count)()` / `(component.get_total)()` 查询状态
- 通过 `register_handler` 绑定到 Scheduler dispatch 路径
- 通过 Scheduler 消息队列实现异步通信

### 执行路径对比

| 特性 | Native | Wasm（模拟·L0） | Wasm（沙箱·L2 WAMR） |
|------|--------|----------------|---------------------|
| 调用方式 | HandlerRegistry 函数指针 ~2ns | WasmRuntime Native 回调 ~2ns | WAMR FFI ~500ns+ |
| 内存模型 | 共享进程堆 | 共享进程堆 | 独立线性内存（Wasm 沙箱） |
| 安全隔离 | 无（依赖类型系统） | 无（开发/测试用） | 完整沙箱（WAMR） |
| 适用场景 | 系统服务、性能关键 | 开发调试、原型验证 | 第三方代码、用户插件 |
| 状态 | ✅ 生产就绪 | ✅ 开发/测试就绪 | ✅ stub 就绪（需链接 WAMR 库） |

## 性能架构（双模运行时更新）

我们采用了三层性能优化策略，以及新增的调度优化：

### 第一层：语言层面（MoonBit 内置）

| 特性 | 说明 | 受益代码 |
|------|------|---------|
| **值类型** | 结构体存储在栈上，避免堆分配 | [MemoryBlock](../runtime/core/memory_pool.mbt#L6-L10)、[ComponentInfo](../runtime/scheduler/scheduler.mbt#L22-L28) |
| **Int ID 替代 String** | 栈上分配，比较只需一条指令 | [Message from/to](../runtime/core/message.mbt#L28-L53) |
| **Native 编译** | 直接编译为机器码，不需要 VM | 所有代码 |

### 第二层：数据结构优化（我们做的）

| 优化 | 前 | 后 | 提升 |
|------|---|----|------|
| **组件表** | `Map[String, ComponentInfo]` | `FixedArray[Option[ComponentInfo]]` | ~50x |
| **内存池** | `Map[String, MemoryBlock]` | `FixedArray[MemoryBlock]` + 栈 | ~10x |
| **环形队列** | `FixedArray[Option[T]]` | `FixedArray[T]` (无装箱) | ~4x |
| **消息 ID** | `String` 类型 | `Int` 类型 | ~50x |

### 第三层：调度器 V2 优化

| 优化 | 说明 |
|------|------|
| **组件亲和度** | 追踪组件间通信模式，记录 last_comm_with 和 last_comm_count |
| **批处理模式** | `run_loop` 循环一次处理多条消息，减少调度开销 |
| **句柄安全** | 集成 MemoryManager，管理句柄所有权、引用计数、自动释放 |
| **动态批大小** | 可配置 batch_size 参数，根据负载调整 |

### 第四层：双模运行时优化（2026-05）

| 优化 | 说明 |
|------|------|
| **dispatch 热路径优化** | 消除 Native/Wasm 分支重复代码，~78 行 → ~35 行 |
| **Native 直接调用** | 绕过 Wasm 序列化，函数指针 ~2ns 直达处理逻辑 |
| **HandlerRegistry** | 固定的 FixedArray 索引，O(1) 查找处理器 |

### 第五层：混合架构（未来）

```
MoonBit 调度核心 (90% 代码，90% C 性能)
   +
 Rust/C 硬件驱动 (10% 代码，100% 性能)
   =
 整体 ~95% C 语言性能
```

## 数据流（V2 更新）

### 启动流程（自举验证版）

```
main()
 ├── [Step 1] 初始化调度器 V2
 │   ├── 创建 RingBuffer（高优 65/普通 257/低优 129）
 │   ├── 创建 MemoryPool（64 块 × 4KB）
 │   ├── 创建 MemoryManager（句柄安全系统）
 │   └── 创建组件表（32 槽位，含亲和度追踪字段）
 │
 ├── [Step 2] 注册调度核心 (ID 0)
 │   └── 调度核心自注册，ID 固定为 0
 │
 ├── [Step 3] 加载自举配置
 │   └── 从内置字符串加载（简化版格式）
 │
 ├── [Step 4] 配置驱动注册组件
 │   ├── 注册 logger (ID: 1)
 │   ├── 注册 counter (ID: 2)
 │   ├── 注册 display (ID: 3)
 │   └── ...
 │
 ├── [Step 5] 测试消息分发
 │   ├── 发送测试消息给调度核心 (ID 0)
 │   └── 消息发送时更新组件亲和度数据
 │
 └── [Step 6] 运行调度循环 (批处理模式)
       ├── process_batch() → 一次处理 batch_size (8) 条消息
       ├── dequeue(高优队列) → dispatch 或跳过
       ├── dequeue(普通队列) → dispatch 或跳过
       ├── dequeue(低优队列) → dispatch 或跳过
       └── 迭代完成后打印状态

消息生命周期:
  发送方 → enqueue → RingBuffer → batch dequeue → dispatch → 接收方
                                                    │
                                              MemoryManager
                                          所有权转移 + 自动释放
```

### 句柄安全流程（V2 新增）

```
分配句柄:
  组件 A → MemoryManager.allocate_handle(owner_id=A, size=4096)
      → 返回 handle_id=N
      → MemoryManager 记录 owner_id=A

发送消息:
  组件 A → send_medium(from=A, to=B, handle=N)
      → Scheduler 调用 MemoryManager.retain_handle(N, A)
      → 消息入队
      → 更新 A 的亲和度数据（增加与 B 的通信计数）

分发消息:
  Scheduler.dispatch(msg)
      → 检查 to_id 有效
      → MemoryManager.transfer_ownership(N, A, B)
      → 如果 auto_free=true，MemoryManager.free_handle(N, B)
      → 消息送达组件 B
```
