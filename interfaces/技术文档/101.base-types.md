# Base Types 接口文档

## 概述

`base/types.wit` 定义了一多 OS 中所有接口共享的基础数据类型。这些类型是整个系统的基础，被所有其他接口引用。

WIT 文件位置：[../base/types.wit](../base/types.wit)

---

## 核心类型

### buffer (数据缓冲区)

```wit
type buffer = list<u8>
```

**说明**：通用的二进制数据缓冲区，用于存储任意二进制数据。

**用途**：
* 文件读写
* 网络数据包
* 图像/音频数据
* 任何需要原始字节流的场景

**使用示例**：
```
// 读取文件到 buffer
let data: buffer = read-file("path/to/file")

// 发送 buffer 到网络
send-network(data)
```

---

### path (文件路径)

```wit
type path = string
```

**说明**：用于表示文件系统路径的字符串类型。

**用途**：
* 文件操作
* 目录遍历
* 路径解析

**路径格式**：
* 支持绝对路径和相对路径
* 遵循各平台的路径分隔符规范（Windows 使用 `\`，Unix-like 使用 `/`）

**使用示例**：
```
let config-path: path = "/etc/config.yaml"
let log-path: path = "./logs/app.log"
```

---

### color (颜色)

```wit
type color = {
  r: u8,
  g: u8,
  b: u8,
  a: u8,
}
```

**说明**：RGBA 颜色表示，每个通道使用 8 位无符号整数。

**字段含义**：
| 字段 | 说明 | 取值范围 |
|------|------|---------|
| `r` | Red（红色） | 0-255 |
| `g` | Green（绿色） | 0-255 |
| `b` | Blue（蓝色） | 0-255 |
| `a` | Alpha（透明度） | 0-255 |

**常见颜色示例**：
```
// 不透明红色
let red: color = {
  r: 255,
  g: 0,
  b: 0,
  a: 255,
}

// 半透明蓝色
let semi-blue: color = {
  r: 0,
  g: 0,
  b: 255,
  a: 128,
}

// 完全透明
let transparent: color = {
  r: 0,
  g: 0,
  b: 0,
  a: 0,
}
```

### timestamp (时间戳)

```wit
type timestamp = u64
```

**说明**：表示时间的无符号 64 位整数，通常是 Unix 时间戳（自 1970 年 1 月 1 日以来的毫秒或微秒数）。

**用途**：
* 记录事件发生时间
* 数据时间戳
* 缓存过期控制
* 性能测量

**单位约定**：
* 建议统一使用**毫秒**作为 timestamp 的单位
* 如果需要更高精度，可以使用微秒或纳秒

**使用示例**：
```
// 获取当前时间戳
let now: timestamp = get-current-time()

// 计算两个时间的差值
let elapsed = now - start-time
```

---

### size (大小)

```wit
type size = u32
```

**说明**：表示数据大小、长度、尺寸等的无符号 32 位整数。

**用途**：
* 文件大小
* 缓冲区长度
* 数组/列表大小
* 图像尺寸

**使用示例**：
```
// 获取文件大小
let file-size: size = get-file-size(path)

// 分配指定大小的缓冲区
let buffer-size: size = 1024 * 1024  // 1 MB
```

---

### offset (偏移量)

```wit
type offset = u32
```

**说明**：表示文件或数据结构中的偏移位置的无符号 32 位整数。

**用途**：
* 文件定位（fseek）
* 数组索引
* 内存偏移

**使用示例**：
```
// 从文件偏移处读取
let data = read-file-at(path, offset: 1024)

// 移动到偏移位置
seek-file(file, offset)
```

---

### result<T, E> (结果类型)

```wit
type result<T, E> = {
  ok: T,
  err: E,
}
```

**说明**：泛型结果类型，用于表示一个操作可能成功或失败。这是一多 OS 中错误处理的基础。

**类型参数**：
* `T`：成功时返回的类型
* `E`：失败时的错误类型（通常是 `base/error.wit` 中定义的 `error` 类型）

**使用示例**：
```
// 成功时的 Result
let success: result<buffer, error> = {
  ok: data-buffer,
  err: error-none,
}

// 失败时的 Result
let failure: result<buffer, error> = {
  ok: empty-buffer,
  err: error-file-not-found,
}
```

## 最佳实践

### 1. buffer 的使用
* 对于较大的数据，考虑使用流（Stream）而不是一次性加载整个 buffer
* buffer 应该在不再需要时及时释放（如果在 Native 环境中）

### 2. path 的使用
* 始终使用绝对路径进行关键文件操作
* 避免硬编码路径，使用配置文件或环境变量
* 处理路径时注意路径分隔符的平台差异

### 3. color 的使用
* 对于透明度，0 表示完全透明，255 表示完全不透明
* 考虑到兼容性，重要的颜色应该提供不透明版本

### 4. timestamp 的使用
* 在整个系统中保持时间单位的一致性
* 记录事件时同时记录时区信息（如果需要跨时区）
* 用于性能测量时，使用高精度计时器

### 5. size 和 offset 的使用
* 对于超过 4GB 的大文件，考虑使用 u64 而不是 size（u32）
* 在处理大文件时，注意整数溢出

### 6. result 的使用
* 每个可能失败的函数都应该返回 Result
* 提供有意义的错误信息
* 不要忽略错误
